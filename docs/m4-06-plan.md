# M4-6 实时系统总验收计划

## 1. 阶段目标

M4-6 只验证并收口已经完成的 M4 实时运行能力，不新增业务功能。验收必须证明：后端权威时间能够完成六事件有限流程，任务与资源状态不会倒退，事件不会重复，候选方案始终经过硬约束复核并等待人工决定，SSE/轮询/重启能够恢复，桌面与移动端可以连续演示三轮。

本阶段完成后才允许将整个 M4 标记完成并进入 M5。M4-6 不接入 AI、真实机场生产数据、随机事件、循环播放、多 worker、PostgreSQL 或新的前端状态机。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 状态所有权与保护边界

- 后端 `RuntimeSessionService`、SQLite 会话记录和 `RuntimeProjectionSource` 继续拥有时间、事件、任务、资源、当前方案和候选方案事实。
- 前端继续只拥有连接恢复、页面选择和操作中的临时状态，不推进时间、不应用事件、不运行规划器。
- 每条控制命令继续携带当前 revision；候选决定继续携带候选 ID。
- 已完成、移动中、等待中和服务中的任务继续冻结；候选只调整未来任务。
- 静态 JSON 只用于运行 API 不可用时的离线只读降级。

## 3. 实施单元

### 3.1 自动化总验收

- 新增独立 M4 验收测试，使用隔离 SQLite 和可注入假时钟，通过公开 REST API 连续执行三轮完整六事件流程。
- 三轮至少覆盖：全部采用、采用与保留交替、重置后重新运行。
- 每轮验证六个场景版本、六个唯一候选、事件只应用一次、候选违规为 0、冻结任务不被改写、09:30 正常完成且不回绕。
- 验证两个独立客户端在同一会话上读取到一致的 revision、时间、事件和方案。
- 验证陈旧 revision、错误候选 ID 和重复命令原子失败，不留下部分状态。

### 3.2 性能与长时间稳定性

- 记录初始 CP-SAT、六次滚动重规划、快照读取和完整一轮的耗时，不把单机结果外推为真实机场承诺。
- 当前小型教学场景每次确定性求解目标不超过 2 秒；超过目标必须记录原因和安全回退结果。
- 使用真实 Uvicorn、Vite 和浏览器按 15x 完成三轮 08:00 至 09:30 流程，覆盖持续 SSE、heartbeat 和页面切换。
- 验收期间监测控制台、后端日志、状态倒退、重复事件、重复候选和进程异常退出。

### 3.3 故障与恢复

- 验证 SSE 主动中断后页面进入恢复状态，连续失败后每 2 秒读取 REST 快照，流恢复后停止轮询。
- 验证旧 stream ID、缓冲缺口和后端重启均以完整权威 snapshot 恢复。
- 验证运行中重启安全转为暂停；等待确认状态重启后保留候选、冻结时间和场景版本。
- 验证一键启停、SQLite 会话找回和两个页面并发操作时的 409 恢复。

### 3.4 浏览器三轮演示

1. 桌面 1440×900：全部采用候选，切换五页并完成全流程。
2. 移动 390×844：采用与保留交替，验证控制、任务、事件、资源和方案内容无横向溢出。
3. 桌面双页面：同一会话保持一致，并在一次连接或服务恢复后完成流程。

每轮均检查安全声明、当前/候选任务书、六事件终态、09:30 完成状态和控制台错误。截图和运行数据保存到忽略提交的 `output/playwright/m4-6/`。

## 4. 验收命令与证据

- 后端专项与全量：项目 `.venv` 运行新增验收测试和全部 pytest。
- Python：`compileall`、`pip check`。
- 前端：`npm run test`、`npm run typecheck`、`npm run build`。
- 脚本：全部 PowerShell 文件语法解析，一键停止/启动闭环。
- 浏览器：真实双服务、桌面/移动/双页面三轮、控制台与响应式尺寸记录。
- 格式与仓库：`git diff --check`、完整差异审阅、工作区仅含 M4-6 文件。
