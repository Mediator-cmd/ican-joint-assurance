# M5-6 AI 辅助总验收计划

## 1. 目标

M5-6 对 M5-0 至 M5-5 已完成的契约、确定性解析、可替换模型适配、人工提交、事实解释和前端交互进行整体收口。验收必须同时证明：无模型时核心闭环完整可用，模型成功时只增强理解和表达，模型故障或受到提示词注入时仍安全回退，并且连续多轮事件不会绕过后端权威状态与人工决定。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 固定基线与范围

- 基线为 M5-5 提交 `5059aeb`；M5-6 不重做前端交互，不新增第二套运行状态。
- 自动验收只使用匿名合成场景、本地假提供方和公开 REST API，不依赖外部模型可用性。
- 可选真实 DeepSeek 冒烟只验证后端 OpenAI-compatible 适配器；密钥仅可由用户在本机后端进程环境中安全输入，不写入源码、文档、测试、命令、日志、响应、前端 bundle 或 Git。
- 本单元不进入 M6，不接真实机场生产数据，不创建 GitHub 远程仓库，不推送代码，不发布公网地址。

## 3. 自动总验收矩阵

| 验收面 | 场景 | 必须证明 |
| --- | --- | --- |
| 无模型 | `deterministic_only` 完成一轮运行事件 | 零提供方调用，草稿可复核，双重确认后才产生候选 |
| 模型成功 | 假模型解析规则难以稳定覆盖的中文表达并解释方案 | 模型输出经过权威实体、原文 quote、时间与 `FACT-*` 白名单复核 |
| 注入与非法输出 | 输入包含“直接执行、自动采用”等越权文本；假模型返回未知实体或非法事实引用 | 越权文本只作为普通输入；安全回退后仍不能自动提交、自动采用或修改状态 |
| 提供方故障 | 超时、请求错误、非法结构 | 事件解析和方案解释均回退确定性结果，响应不泄露内部异常或配置 |
| 连续运行 | 同一 session 连续三轮草稿、提交、候选、解释和人工决定 | revision 与场景版本单调更新，候选 ID 不重复，当前方案只在人工采用后改变 |
| 安全声明 | 辅助响应、页面和文档 | 完整声明原样保留，不暗示真实机场控制能力 |

## 4. 状态所有权核验

- `RuntimeSessionService` 与 SQLite 继续唯一拥有仿真时钟、revision、事件投影、当前方案和候选方案。
- AI 只返回待复核事件字段或引用既有权威事实的表达；不能推进时间、应用事件、生成自由排班或采用候选。
- 运行事件提交必须同时满足 `confirm_event=true` 与有限 `objective_profile + confirm_objective=true`。
- 草稿和解释请求必须绑定当前 version/revision；陈旧请求必须拒绝，不能解释或修改其他上下文。
- 所有候选继续经过确定性 CP-SAT 与独立硬约束复核，并由用户明确采用或保留。

## 5. 浏览器验收

使用真实本地浏览器完成桌面 `1440x900`、移动 `390x844` 和同一会话连续三轮检查：

1. 无模型模式完成草稿、字段复核、目标选择和双重确认；候选不自动采用。
2. `auto` 模式完成模型可用或安全回退路径，并查看当前/候选方案的事实引用。
3. 输入越权文本和更新后的全新事件，确认页面仍要求人工提交与人工决定，旧草稿/解释会过期。
4. 三轮分别采用或保留候选，确认 revision、事件目录、当前方案和候选状态与后端快照一致。
5. 两种视口无横向溢出、无板块内部纵向滚动；控制台无 error/warning；完整安全声明可见。

真实模型不可用、密钥未安全注入或外部网络故障时，浏览器验收仍须用确定性路径完成，且明确记录真实提供方冒烟状态，不能伪造“模型已调用”。

## 6. 自动质量门禁

- Git 跟踪文件、前端源码和构建产物敏感信息扫描。
- `git diff --check`、工作区状态与最终提交核验。
