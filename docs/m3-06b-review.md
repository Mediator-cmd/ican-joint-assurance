# M3-6B 审查记录：五页数据源联调与刷新状态保持

## 审查范围

- 保存并展示唯一 `loadDemoPayload()` 返回的数据来源。
- 让调度总览、任务计划、事件影响、资源态势和方案依据五页继续共享同一份载荷与方案状态。
- 验证 API 在线、静态回退和服务恢复三种情况下的页面、筛选及任务/事件/资源选择一致性。
- 复核 1440×900 桌面端与 390×844 移动端的来源标签、滚动边界和安全声明。

本阶段不新增加载器，不在前端计算调度或比较指标，不调整既有五页信息架构，也不接入自然语言 AI、持久化或真实机场生产数据。

## 实现结果

`App.tsx` 保存 `loadDemoPayload()` 返回的 `DemoDataSource`，并在共享页头和侧栏显示来源状态：

| 数据来源 | 页头标签 | 侧栏状态 | 视觉语义 |
| --- | --- | --- | --- |
| `api` | 服务数据 | 数据服务连接正常 | 绿色，表示本地业务服务已连接 |
| `static_fallback` | 本地演示数据 | 当前使用本地演示数据 | 琥珀色，明确提示当前为内置演示载荷 |

来源标签只说明数据获取路径，不把进程内 API 描述为真实机场生产系统。原有“合成数据”标识继续保留，静态回退时不再显示容易误解的“服务正常”文案。

## 刷新状态一致性

新增 `resolveSelectedId()` 统一处理任务、事件和资源选择：刷新后的数据仍含原 ID 时保持当前选择；原 ID 消失时选择首个可用项；列表为空时清空选择。

刷新开始会暂时清空 `payload`。任务、事件和资源的选择协调 effect 因此必须在新载荷可用后才执行；对应的 `current`/`payload` 守卫已经保留，避免加载中间态提前把用户选择重置为默认值。

应用内刷新前建立了以下可辨识状态：

- 当前页：资源态势。
- 当前方案：原始计划，场景版本 V1。
- 任务筛选与选择：紧急，`TASK-005`。
- 事件选择：第二项 `SIM218` 登机口调整。
- 资源选择：`BUS-01`。

后端停止后点击“重新载入演示数据”，页面进入静态回退且上述状态全部保持；后端恢复后再次点击同一按钮，来源恢复为“服务数据”，上述状态仍全部保持。控制台只有后端停止期间 `/api/v1/demo` 返回 502 的一条预期资源错误，没有 React 或 JavaScript 运行时错误。
