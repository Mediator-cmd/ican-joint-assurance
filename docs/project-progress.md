## 2. 当前项目状态

### 2.1 已确认的产品定位

联保智调是面向机场地面保障人员的仿真与辅助决策系统。它在航班延误、登机口变更、摆渡资源减少等扰动下，对摆渡车、轮椅、服务人员和特殊旅客服务任务进行约束调度，输出可执行、可解释、可复核的任务清单。

### 2.2 已确认的核心价值

1. 硬约束由确定性调度逻辑处理，包括资源容量、服务能力、时间窗和任务不重叠。
2. AI 只负责自然语言事件理解、字段缺失追问和结果解释，不直接生成未经校验的调度结果。
3. 新事件进入后执行滚动重规划，并保留调整前后指标和审计记录。
4. 通过同一仿真场景对比 FIFO 基线与优化方案，量化关键任务逾期、等待时间和资源利用率变化。
5. M4 必须实现后端权威仿真时间、任务与资源状态自动转换、事件到时生效、滚动重规划、人工确认和页面实时更新，不能用固定快照切换替代运行过程。

### 2.3 明确不做的内容

- 不接管真实机场生产系统。
- 不提供真实放行、登机、改签或车辆控制指令。
- 不保存姓名、证件号、联系方式等旅客个人信息。
- 不把仿真或历史回放数据包装成真实生产数据。

所有界面、报告和演示材料应保留“仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。”的安全提示。

## 5. 已确认的技术决策

| 决策 | 当前结论 | 原因/约束 |
| --- | --- | --- |
| 架构 | React + TypeScript 前端，FastAPI + Pydantic 后端 | 便于快速演示、数据校验和接口测试 |
| 调度顺序 | 先 FIFO 基线，再做约束优化 | 先建立可解释的对照组，再量化优化收益 |
| 优化器 | 候选为 OR-Tools CP-SAT 或线性规划 | 适合资源、时间窗和不重叠约束；M2 决定最终模型 |
| 数据库 | M3 使用进程内仓库；API 契约稳定后接 SQLite | 先验证版本和事件语义，降低单人开发成本，并保留 PostgreSQL 适配 |
| AI 边界 | 解析和解释，不直接决定排班 | 防止幻觉绕过硬约束，保证结果可复核 |
| 数据来源 | 匿名化、历史回放或仿真数据 | 不依赖真实机场生产授权，保护个人信息 |
| 首个场景 | 多航班扰动下特殊旅客地面保障资源分配 | 与竞赛交通出行方向和实用性问题直接对应 |
| 场景主格式 | M1 使用 UTF-8 JSON；CSV 适配按实际导入需求后置 | 场景包含多实体和嵌套引用，JSON 可保留完整结构并减少多文件一致性问题 |
| 场景事件语义 | 航班和任务是基线，事件按时间注入 | 避免导入阶段改写原始数据，便于重规划前后对比 |
| 数据分类标识 | 每个场景必须声明 `synthetic` 或 `anonymized_replay` | 禁止未标明来源的数据进入演示和评测流程 |
| 最终展示形态 | 浏览器运行态控制台 + FastAPI + 可复现仿真数据 | 评委无需查看代码即可完成完整操作和指标比较 |
| 优化器 | OR-Tools CP-SAT，分层固定优先级目标 | 先保障 P1，再考虑总完成数、其他优先级和等待/移动成本 |
| 演示数据流 | Python 生成 JSON，前端只负责展示 | 防止前端与后端指标不一致，M3 原契约替换为 API |
| Python 环境 | 项目 `.venv` 隔离安装 | OR-Tools protobuf 6.x 与全局 `mem0ai` protobuf 5.x 不兼容 |
| M3 场景状态 | 进程内仓库 + 防御性深拷贝 + `RLock` + 期望版本校验 | 保证基线不可变、并发写入原子、过期请求不覆盖新版本；SQLite 后置 |
| 产品差异化 | 工作流、确定性计算和证据链优先，AI 仅做输入与解释增强 | 避免聊天套壳；模型不可用时仍能导入、校验、调度、比较和审计 |
| M4 实时语义 | 可复现的仿真实时运行；REST 控制、SSE 推送、短轮询恢复 | 不冒充真实生产数据；后端维护权威时间和状态，前端不随机生成变化 |
| 动态重规划 | 事件触发时自动暂停；冻结已完成和正在执行任务；候选方案需人工确认 | 保护已经发生的事实，避免每秒无意义求解、候选方案过期或静默替换执行计划 |
| M4 运行契约 | `runtime_models.py` + `m4-runtime-contract.md` 为唯一事实来源 | 后端路由、SQLite、SSE 和前端不得各自创建平行时钟、状态或 revision |
| 实时消息编号 | 持久业务 `revision` 与 SSE `stream_id + sequence` 分离 | tick/heartbeat 不写数据库也不增加 revision，但仍可可靠去重和排序 |
| 会话恢复入口 | SQLite 持久化 + 分页会话列表；重启后运行中会话安全转为暂停 | 数据不仅能保存，还必须能被浏览器重新发现并由用户继续 |
| M4 投影恢复 | 每个新运行会话在 SQLite 保存不可变场景版本、确认方案、完整事件目录和已应用事件版本证据 | 重启后即使 M3 进程内方案对象已消失，也能按同一时间重建完全一致的运行快照 |
| M4 跨版本运行聚合 | 同一 SQLite JSON 聚合同时保存初始场景/方案、当前事件场景、当前确认方案、候选方案、冻结任务和事件决定证据 | 事件后当前场景可先于 active plan；拒绝候选和重启均不能丢失旧方案或已发生事实 |
| M4 实时流 | 每会话一个进程内 `RuntimeStreamBroker`、共享 `stream_id + sequence` 和 256 条环形缓冲 | 消息层只采样权威快照与 SQLite 审计；旧流、缺口或服务重启统一回到完整 snapshot |
| M4 前端状态所有权 | 五页共享一个 `RuntimeSessionSnapshot`；浏览器只拥有连接、轮询和页面选择 | 前端不推进时钟、不推导任务/资源/事件状态、不运行规划器；旧 REST 响应不得覆盖较新的权威状态 |

## 8. 问题、风险与处理方式

### 已知问题

1. 项目尚未创建 GitHub 远程仓库，原因是仓库名称尚未最终确认。
2. M3 场景、计划和业务审计仍为进程内存储；M4 运行会话、控制审计和确定性投影依据已进入 SQLite。比赛版重启可恢复运行会话，但通用场景/方案持久化仍未完成。
3. 真实机场数据接入需要数据授权、脱敏和接口适配，不作为比赛 MVP 的前置条件。
4. M4-5 已让在线五页消费 SQLite 运行会话、SSE 和 REST 恢复；M4-6 尚未完成长时间、性能、故障、多页面一致性和桌面/移动三轮连续演示，因此仍不能将整个 M4 标记完成。
5. M4-4 流缓冲只属于单个 Uvicorn 生命周期，不提供多 worker 或跨进程消息补发；服务重启、旧流或缓冲缺口会发送 SQLite 权威 snapshot，这符合单机比赛版边界。

### 已解决问题

1. 首轮测试发现唯一 ID 辅助函数的列表推导变量错误，导致合法场景触发 `NameError`；已改为显式传入 ID 字段，并用合法场景和重复资源测试验证。
2. 当前执行环境不能写入系统 pytest 临时目录；损坏 JSON 测试已改用仓库内固定夹具 `tests/fixtures/invalid-json.json`，避免环境依赖。
3. Windows 控制台初次输出中文摘要时编码不一致；验证脚本已显式使用 UTF-8 输出并复测通过。
4. OR-Tools 全局安装会升级 protobuf 并与现有 `mem0ai` 冲突；已撤销全局变更，改为项目 `.venv` 隔离安装。
5. 首轮前端生产构建受沙箱子进程权限限制；在获准环境中构建成功，代码本身无构建错误。
6. 首次浏览器加载出现 favicon 404；已添加 `frontend/public/favicon.svg`，复测控制台 0 错误。
7. FastAPI 0.140.7 / Starlette 1.3.1 对旧 `httpx` 测试客户端发出弃用警告；已按本地源码提示改用 `httpx2` 2.9.1，复测无警告。
8. 首版 500 异常日志会记录异常原文，可能包含本地路径；已改为只记录请求 ID 和异常类型，并添加响应与日志双重脱敏测试。

### 风险控制

- 不把外部 API 密钥写入代码或文档。
- 不在日志、截图、演示视频中出现可识别个人信息。
- 对 AI 解析结果执行 Pydantic 校验和硬约束校验；模型不可用时保留规则回退。
- 任何性能指标均标注为仿真测试目标，不外推为真实机场生产承诺。
