# M3-4 审查记录：结构化事件与可理解的计划 API

## 审查范围

- 待处理事件和新增结构化事件的版本化应用。
- 从不可变基线重放事件，避免延误和登机口变化重复累计。
- FIFO 原规则方案与 CP-SAT 系统优化建议的创建、不可变保存、列表和详情查询。
- 保存前的场景版本复核、独立硬约束复核和计划审计记录。
- 普通语言结果摘要、取舍说明、推荐动作和安全边界。

## 新增接口

| 方法与路径 | 普通用户含义 | 关键结果 |
| --- | --- | --- |
| `POST /api/v1/scenarios/{scenario_id}/events/apply` | 把选中的航班变化计入当前场景 | 返回新版本、已应用/待处理事件和下一步建议 |
| `POST /api/v1/scenarios/{scenario_id}/plans` | 生成原规则方案或系统优化建议 | 返回完整方案、普通语言解释、人工确认提示和安全声明 |
| `GET /api/v1/scenarios/{scenario_id}/plans` | 查看该场景已经算过的方案 | 支持版本和 `fifo/cp_sat` 筛选，直接返回核心结论与取舍 |
| `GET /api/v1/plans/{plan_id}` | 复核一个完整方案 | 返回任务、资源、时间、未分配原因、约束结果和解释 |

## 一致性与安全审查

1. 每次事件修订都从不可变基线重新应用全部已确认事件，第二批事件不会把第一批延误再加一次。
2. 事件批次只让版本增加 1；计划生成不改变场景版本。
3. 事件应用和计划保存都在提交时复核 `expected_version`，过期请求返回 409 且不写版本、计划或审计。
4. 计划保存后使用防御性深拷贝；修改调用方对象或查询结果不会改变仓库内容。
5. 同一场景版本和算法不重复创建第二份同 ID 计划，返回已有方案查询指引。
6. 计划生成后再次调用独立约束检查器；演示 FIFO 和优化方案的冲突数均为 0。
7. 新事件引用未知航班、登机口前态不一致或超出场景数据边界时，返回安全业务错误，不回显内部异常或整份输入。
8. 没有任务或可用匹配资源的场景不会返回“0 项任务全部完成”，而是明确提示先补全场景。

## 可理解性审查

API 保留内部算法标识用于复现，但给最终界面直接提供确定性普通语言字段：

- `fifo` 显示为“原规则方案”，解释为按任务出现顺序安排。
- `cp_sat` 显示为“系统优化建议”，解释为先保护紧急任务，再减少未安排任务和等待。
- `result_summary` 先回答安排了多少任务、紧急任务是否得到保障。
- `tradeoff_summary` 明确平均等待和优先级取舍，不只展示一个优化分数。
- `recommended_action` 指出下一步是人工确认、补充资源还是先处理冲突。
- `calculation_basis` 明确结论来自人员/车辆、地点、移动时间、截止时间、容量和重复占用检查。

这些解释由结构化规则生成，不调用自然语言 AI；同一计划始终得到相同解释。

## 剩余边界

- M3-4 尚不提供方案比较和公开审计时间线；这两项属于 M3-5。
- 前端仍读取静态演示 JSON；API 优先与静态回退属于 M3-6。
- 计划和场景仍为进程内临时数据；服务重启后恢复内置演示场景。
- 本阶段不接入自然语言 AI，不接入真实机场生产数据，也不生成真实运行指令。
