# M6-1 确定性规模场景工厂审查

## 1. 结论

M6-1 已完成。项目现在可以从 `small`、`medium`、`large_aggregate` 三个规范档位独立生成 100/500/2000 项任务、20/50/200 项资源和 5/10/20 个区域的严格 `Scenario`，并返回可复核的 SHA-256 内容指纹。

所有实体均为固定日期下的匿名合成教学数据。工厂不读取网络、系统时间、AI 配置、运行会话、用户输入或真实机场数据，也不创建运行事件、规划结果或性能报告。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 生成规则

- 场景窗口固定为 `2026-08-01 08:00+08:00` 至 `20:00+08:00`，版本固定为 1，`run_mode=simulation`，`data_classification=synthetic`。
- 区域使用 `ZONE-*` 合成编号，构造完整、对称、确定性的有向路网；每个区域包含到全部区域的非负分钟数。
- 三个档位分别生成 10/50/200 个 `FL-SCALE-*` 航班，展示号只使用 `SCL*`；每个航班都被至少一个任务引用。
- 任务使用 `TASK-SCALE-*`，按固定规律覆盖四种任务类型、三种资源类型和三种匿名乘客分组。起终点不同，释放时间、截止时间和服务时长全部落在场景窗口内。
- 资源使用 `BUS-*`、`WC-*`、`AGENT-*` 合成编号，三种类型均存在，固定为可用状态并覆盖整个场景窗口。每项任务至少存在类型和容量匹配的资源。
- 场景 `events=[]`。M6-1 不制造循环、随机或运行时扰动，不触碰现有 SQLite session/revision、当前方案、候选方案或人工决定。

## 3. 指纹与篡改防护

指纹对 `Scenario.model_dump(mode="json")` 进行键排序、紧凑 JSON 编码，并在固定 `ican-m6-scale-scenario-v1` 命名空间下计算 SHA-256。`ScaleScenarioArtifact` 同时绑定规范 `ScaleProfile`、场景和摘要，并重新检查档位计数、合成分类、仿真模式、空事件集和摘要一致性。

| 档位 | 任务/资源/区域/航班 | 冻结 SHA-256 |
| --- | --- | --- |
| `small` | 100 / 20 / 5 / 10 | `7dc3827de6a1d702f73a2383473008f04170ba3ed1491e1817bcab73bb0bcf11` |
| `medium` | 500 / 50 / 10 / 50 | `5775f0c58d2d64e47cca1a8879ae14077ea65236a66f18a15816ce244a73d649` |
| `large_aggregate` | 2000 / 200 / 20 / 200 | `a5e0bae31aa7a91b70568df58326fe93a850ce26d3701234a39e14e620c9c70e` |

相同档位连续生成得到相同模型和摘要，但返回不同对象；修改一个任务字段后摘要立即变化，携带旧摘要重新构造工件会被 Pydantic 拒绝。模型 JSON 往返后仍保持相同场景和摘要。

## 4. 完整性验证

专项测试逐档验证：

- 任务、资源、区域和航班计数与规范档位完全一致；
- 所有任务到航班、起终区域以及所有资源到区域的引用闭合；
- 路网覆盖全部区域且双向分钟数一致；
- 所有任务和资源时间落在固定窗口，任务时长不超过自身时间窗；
- 三种资源类型和四种任务类型均被覆盖，任务人数不超过匹配资源类型的最大容量；
- 固定指纹、调用隔离、JSON 往返、内容篡改和未知档位拒绝均通过。

## 5. 阶段边界与下一入口

M6-1 没有调用或修改 FIFO、CP-SAT、`validate_plan()`、公开 API、前端、SQLite 或 AI 链路，也没有生成基准样本、性能报告或回退结果。因此当前只能证明规模输入可复现、引用完整，不能声称任何规划档位已经达到性能目标。

下一唯一入口为 M6-2：实现有界可扩展规划、模型规模保护和只对 `large_aggregate` 开放的显式安全回退。所有输出仍必须形成现有 `Plan` 并经过独立硬约束复核；不得提前生成 M6-3 性能结论、接入真实机场生产流或部署公网。
