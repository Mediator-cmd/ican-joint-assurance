# M7 发布准备与公网地址规划

## 1. 目的与边界

M7 负责把已完成的 M6 仿真版本整理为可公开审阅、可复现构建、可按说明部署的比赛交付物，并在外部发布决策确认后再创建 GitHub 远程和稳定公网地址。

本阶段仍保持以下边界：

- 只使用匿名合成教学数据和项目原创 2D 空间示意图，不接真实机场生产系统、真实坐标、内部运行图或旅客个人信息。
- AI 只读解释和事件理解；不应用事件、推进仿真时钟、采用候选方案或控制资源。
- 单 origin、单实例、一个 Uvicorn worker、SQLite 持久化卷是首次公开版本的明确限制。
- DeepSeek 密钥只由部署平台 Secret Manager 注入后端进程，不进入 Git、Dockerfile、镜像层、前端构建产物或日志。

## 3. 发布架构契约

### 3.1 首次公开版本

```text
公网 HTTPS
  -> 一个应用副本
  -> 一个 Uvicorn worker
  -> FastAPI + Vite 同源服务
  -> 持久化卷 /data/runtime-sessions.sqlite3
```

- 平台必须支持自定义 Dockerfile、`PORT`、健康检查和持久化磁盘。
- 健康检查固定为 `GET /api/v1/health`，必须返回 HTTP 200 和 `status: ok`。
- 只配置一个副本。SQLite、内存 SSE 缓冲和运行会话恢复均不支持横向扩容。
- 健康检查失败时平台应停止流量并按平台策略重启；不允许通过多个副本掩盖 SQLite 锁或 SSE 状态问题。
- 发布前后的 smoke 必须验证：首页 200、健康检查 200、创建/恢复匿名仿真会话、AI 未配置时确定性回退可用。

### 3.2 Secret Manager

只允许配置以下后端变量：

| 变量 | 是否必需 | 说明 |
| --- | --- | --- |
| `AI_API_KEY` | 可选 | DeepSeek API 密钥；平台 secret，不写入普通环境变量清单 |
| `AI_BASE_URL` | 配置 AI 时必需 | OpenAI-compatible 根地址，例如 `https://api.deepseek.com` |
| `AI_MODEL` | 配置 AI 时必需 | 已验证模型名由部署前 smoke 确认 |
| `AI_TIMEOUT_SECONDS` | 可选 | 模型请求超时；保持有限值 |

未配置 AI 时，事件规则解析、CP-SAT 调度、方案解释和空间问答的确定性路径仍必须可用。模型调用只增强表达，不能成为核心闭环的启动前置条件。

### 3.3 回滚

1. 保留上一份已验收镜像和上一份 Git commit 的可构建来源。
2. 新版本先通过健康检查和匿名闭环 smoke，再切换公网流量。
3. 若健康检查、SQLite 恢复、模型只读边界或演示流程失败，立即切回上一镜像；不要在故障期间修改生产 SQLite 文件结构。
4. 回滚后保留部署日志中的版本标识、失败检查项和时间，不记录密钥、用户原文或旅客信息。

## 6. 禁止事项

- 不把 DeepSeek key、任何 `.runtime` 文件、SQLite 会话、服务日志或截图缓存加入 Git。
- 不把“本地地址”“平台预览地址”写成稳定公网地址。
- 不把匿名机场示意图描述成北京大兴机场或真实生产地图。
- 不把模型回答描述为放行、登机、改签、车辆控制或真实运行指令。
- 不在未确认仓库名、可见性和托管平台前运行 `gh repo create`、`git remote add`、`git push` 或部署命令。
