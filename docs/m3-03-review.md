## 与通用 AI 套壳的区分

1. 当前三个场景端点完全不调用 AI，所有摘要、警告和推荐动作由可复核规则生成。
2. 用户首先看到可操作的业务场景和资源缺口，而不是空聊天框。
3. 每条场景记录包含数据分类、版本、事件状态、临时存储和安全边界，避免模型用自然语言掩盖数据来源。
4. 系统只在数据真的具备可用任务和匹配资源时声明可规划，不能靠模型文案制造“看起来可用”的假象。
5. 错误响应保留匿名实体 ID，使保障人员能定位问题；同时不回显原始输入中的无关内容。

## 审查中发现并解决的问题

1. 初版测试错误地要求隐藏 `TASK-001`。审查确认匿名任务 ID 是必要的定位证据，不属于旅客个人信息，因此改为保留 ID、禁止回显整份原始输入。
2. 初版只要存在任意可用资源就标记可规划，会误导“任务需轮椅但只有服务人员”的场景。现改为至少一种可用资源类型与任务需求匹配，并增加专项测试。
3. 原计划将场景列表定义为裸数组，不利于分页和最终界面判断。M3-3 将其细化为包含总数和窗口信息的 `ScenarioListResponse`。

## 剩余边界

- M3-3 只读取场景状态；事件应用、FIFO/CP-SAT 计划和方案查询属于 M3-4。
- 内置示例当前通过公开 API 只读，服务重启会恢复初始状态。
- 前端尚未读取这些接口；API 优先和静态回退属于 M3-6。
- 当前推荐动作描述下一业务步骤，但对应规划端点要在 M3-4 后才可执行。

## 审查结论

未发现阻塞 M3-3 提交的问题。下一执行单元为 M3-4，继续坚持“AI 不可用仍能工作”：先完成结构化事件和确定性计划 API，再考虑自然语言输入。
