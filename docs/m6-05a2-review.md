# M6-5A-2 空间 AI 问答与地图聚焦审查

## 1. 审查结论

M6-5A-2 已完成。调度总览的空间态势现在具备绑定当前 `session_id + revision + layout_id` 的只读问答，能够识别完整 ID 与 `task4`、`任务4`、`wc1`、`事件2`、`E2` 等唯一可确定简写，并把回答引用的任务、资源、事件和匿名区域在同一权威地图上聚焦。

AI 只参与当前事实的相关性选择，不能生成或修改坐标、路线、进度、事件、方案或操作。模型选中的引用和聚焦必须通过后端白名单校验，最终回答正文再由后端按被引用的 `SPATIAL-FACT-*` 重建；模型自由文本及其自行添加的操作建议不直接透传。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 后端契约、grounding 与模型边界

- 新增 `POST /api/v1/assistant/spatial-questions`，请求必须携带当前运行会话、revision、问题、可选地图选择和 `auto | deterministic_only` 模式。
- 服务在同一次调用内读取该 revision 的 `RuntimeSpatialView`。未知会话、陈旧 revision 或不属于当前 overlay 的选择均明确拒绝；问答不写 SQLite、不增加 revision，也不改变现有运行快照。
- 问题中的明确实体优先于页面默认选择，避免 `TASK-001 / BUS-01 / EVT-SIM102-DELAY` 等偶然选择污染 `task4` 的答案。事件事实同时关联受影响任务和当前候选变化，使“事件怎么处理”可以联动事件、任务、候选路线与人工确认边界。
- 未登记对象、真实机场位置/坐标、内部运行图以及采用候选、推进时间、控制车辆等执行请求直接返回 `question_not_grounded`，不调用模型猜测。
- 模型只收到规范化问题、当前选择、允许聚焦 ID 和经过筛选的匿名空间事实；不发送 session ID、revision、仿真时间、SQLite、审计、本机路径、密钥或 context fact。
- 模型未配置、超时、提供方错误、结构非法、引用越界或聚焦无事实支持时，均透明回退确定性规则。响应固定 `requires_human_confirmation=true`、`modifies_runtime=false`。

## 3. 前端问答与地图联动

- 空间态势图下方新增“空间态势 AI 问答”，可选择智能辅助或仅规则，并提供整体态势、事件位置、任务路线和候选变化问题模板。
- 回答完整展示实际问题、来源、question ID、revision、仿真时间、匹配对象、权威引用、地图聚焦对象、未解决问题和安全声明，内容自然展开且没有内部滚动。
- 后端批准的聚焦对象使用独立紫色高亮；它只改变视觉强调，不替换当前实线、候选虚线、资源权威位置或现有选择所有权。
- 问题、模式、任务/资源/事件选择、session、revision 或 layout 任一变化时，旧回答和地图 AI 聚焦立即清除；旧请求即使稍后返回也不能重新显示。

## 4. 真实浏览器证据

- 真实 DeepSeek `deepseek-v4-flash` 在页面默认选择为 `TASK-001 / BUS-01 / EVT-SIM102-DELAY` 时回答“`task4现在在哪里，由哪个资源执行？`”，只引用 `SPATIAL-FACT-TASK-004-ACTIVE`，回答及地图聚焦只涉及 `TASK-004`、`WC-01`、`TRANSFER-DESK`、`GATE-E01`，没有混入默认选择。
- 询问“北京大兴机场的精确坐标是什么？”时返回“当前空间事实不足 · 未调用模型猜测”，明确说明只有原创匿名空间示意，不包含真实机场坐标、内部运行图或未授权位置；结果存在但 AI 聚焦对象和地图高亮均为 0。
- 修改问题后旧结果/高亮为 `0/0`；更换地图任务选择后同样为 `0/0`；人工重新计算使权威 revision 从 R53 更新到 R55 后，旧结果和原有 4 个地图高亮再次归零。
- 390×844 下 document/body 宽度均为 `390/390`，问答面板为 `368/368` 且高度 `938/938`，回答为 `368/368` 且高度 `520/520`；面板和回答均完整展开，无横向溢出或内部纵向滚动。控制台为 0 error、0 warning。
