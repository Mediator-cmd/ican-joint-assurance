# M4-5 五页实时运行工作台审查记录

## 1. 审查结论

M4-5 已完成。正常在线流程现在直接创建或找回 SQLite 运行会话，五个工作页共享同一份后端权威快照、连接状态和页面选择，并通过 SSE 自动更新。静态三快照只在运行服务不可用时作为明确的离线只读降级，不再承担正常运行过程。

审查中发现的 SSE 恢复竞态、重复控制窗口和旧快照倒退风险均已修正，未遗留高、中、低优先级代码问题。

所有在线与离线页面继续完整显示：

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

M4-6 尚未开始，M4 整体尚未达到长时间、性能、故障和三轮连续演示退出条件。

## 2. 已实现范围

### 2.1 会话恢复与共享状态

- 页面先取得 `/api/v1/demo` 的初始合成场景和确定性 CP-SAT 初始方案，再按场景读取最近更新的 SQLite 会话。
- 只有 `initial_scenario_version` 与 `initial_plan_id` 同时匹配时才复用会话；没有匹配项才创建。刷新页面不会重复建立会话。
- `RuntimeWorkspace` 是在线五页的共同容器，唯一持有 `RuntimeSessionSnapshot`、连接状态以及任务、资源和事件选择；没有页面级时钟或第二套任务状态机。
- 任务、资源、航班、事件、guidance、revision、场景版本和方案 ID 均直接来自后端投影。前端不重新计算业务状态、指标或规划结果。

### 2.2 SSE、轮询与并发保护

- `runtime.snapshot` 原子替换完整快照，`runtime.tick` 只替换后端 clock；所有流消息按 `stream_id + sequence` 去重，不能用业务 revision 丢弃 tick 或 heartbeat。
- SSE 连续失败三次后进入每 2 秒 REST 快照恢复；收到新的有效流消息后立即停止轮询。
- SSE 恢复时会忽略已经在途的旧轮询响应，避免页面重新退回“快照恢复”或用旧时钟覆盖新流。
- 完整快照按会话、revision 和同 revision 的仿真时间进行单调性保护；高 revision 的明确重置仍允许时间回到窗口起点。
- 开始、暂停、倍速、重置、手动重规划和候选决定都携带当前 `expected_revision`；候选决定另带当前候选 ID。
- 控制请求使用同步 busy 引用封闭快速重复点击窗口。409 后只重新读取权威快照并提示用户重新确认，不自动重放旧命令。

### 2.3 五页动态工作流

- 统一控制条始终显示仿真时间、下一边界、会话状态、场景版本、revision、连接状态、开始/暂停、`1x/5x/15x`、重置和合适的手动重规划入口。
- 总览直接回答当前事实、系统动作和需要人工决定的事项，并汇总任务状态、活动资源、下一事件和候选状态。
- 任务页按后端实时状态筛选，展示执行资源、当前位置、下一边界、受影响事件和冻结事实；筛选和跨页选择不触发规划。
- 事件页展示事件处理状态、应用版本、候选关系，以及航班当前预计时间、登机口和最近变化。
- 资源页展示区域间移动进度、当前/下一任务和下一可用时间；静止资源不重复绘制相同起终点，也不伪造经纬度轨迹。
- 方案页只展示当前执行方案、候选 ID、受影响任务和后端独立约束复核语义。当前快照不提供可复核的候选指标，因此页面没有伪造指标或比较值。
- 待确认候选只有在用户明确采用后才替换 active plan；“保留当前方案”会拒绝候选并保留原执行方案。

### 2.4 离线只读与非循环语义

- 运行 API 不可用时回到原有五页静态展示，所有位置明确显示“离线只读”或“时间不会推进”，不启动本地计时器，运行控制不可用。
- 运行从场景窗口起点单向推进到完成，不自动循环播放。相邻更新来自新的后端仿真时间和业务边界，不通过随机数制造变化。
- 页面保留 M3 的五页结构、跨页选择、算法证据、可读性层和静态回退能力，没有舍弃既有优势。

## 3. 审查发现与修正

1. SSE 恢复并停止轮询后，已经发出的 REST 请求仍可能稍晚返回，覆盖更新的流快照并把连接状态改回“快照恢复”。现由当前 SSE 可用代际拦截该响应，恢复后不再接受在途轮询结果。
2. 仅依靠 React 下一次渲染禁用按钮，无法完全封闭同一事件循环内的快速重复点击。现增加同步 `controlBusyRef`，第一条命令发出后立即拒绝第二条。
3. 控制响应、轮询响应与 SSE 可能以不同网络顺序到达。现拒绝较低 revision 以及同 revision 下更早仿真时间的完整快照，同时允许更高 revision 的重置回到起点，防止状态倒退。
4. 航班原始枚举直接显示会增加理解成本，现统一映射为计划中、登机中、已延误和已起飞。
5. 资源静止时 `to_zone_id` 为空，页面只显示当前区域，不再用箭头重复同一地点。
6. 人工网络拦截会在浏览器控制台产生预期的请求失败记录；这些记录只用于验证 SSE、REST 和全 API 故障分支，不作为正常在线控制台结论。

## 5. 已知边界

- 本单元只接入可复现、可审计的教学仿真实时数据，不接真实机场生产数据、生产消息总线或控制系统。
- 当前运行场景仍是固定的合成教学场景；M4-5 不实现随机场景生成。后续场景生成必须带来源和种子，并保持可复现，而不是循环播放。
- AI 事件解析、缺失字段追问、候选解释和风险提示属于后续阶段；AI 不能替代确定性规划、硬约束复核或人工确认。
- 候选快照目前只公开方案 ID、受影响任务和违规为零的后端语义，未公开完整指标差值；前端不会猜测或伪造这些数据。
- SSE 缓冲仍是单 worker 进程内资源；服务重启、旧流或缓冲缺口依靠完整 SQLite 权威 snapshot 恢复。
- M4-6 仍需完成长时间、性能、故障、多个页面一致性以及桌面/移动三轮连续演示，不得据此提前宣称整个 M4 已完成。

## 6. M4-6 唯一入口

M4-6 应只做阶段总验收和为验收发现的问题收口：执行完整动态场景到完成，覆盖长时间与性能、服务/连接故障、多页面同步、重启恢复以及桌面和移动端三轮连续演示，确认无状态倒退、重复事件、阻塞或安全声明缺失。M4-6 不应借验收名义接入真实机场生产数据、AI 解析、随机场景生成、多 worker 或 PostgreSQL。
