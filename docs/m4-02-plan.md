# M4-2 确定性运行状态投影实施计划

## 1. 目标

在不实现自动事件应用、滚动重规划、SSE 或前端实时控制的前提下，让 `RuntimeSessionSnapshot` 中的任务、资源、航班和事件数组由“会话持久化输入 + 后端权威仿真时间”确定性生成。

同一会话、同一 revision、同一仿真时间必须得到完全一致的投影；普通查询和时钟 tick 不增加 revision，不写控制审计。

## 2. 数据依据与恢复

M3 的场景和方案仓库仍在进程内，且基线 `Scenario.events` 不包含待发生事件。M4-2 为每个新运行会话持久化一份内部投影依据：

- 创建会话时选择的不可变场景版本；
- 当前已确认方案；
- 该场景的完整事件目录；
- 已经包含在所选场景版本中的事件及其准确 `version_after`。

这些数据只用于匿名化教学仿真的状态重建，不包含个人信息。SQLite 旧库通过增加可空 JSON 列兼容 M4-1；旧会话若仍能从进程内仓库找到场景和方案，则补写投影依据但不增加业务 revision。无法补写的旧会话继续保留 M4-1 空投影，不伪造数据。

## 3. 状态规则

### 3.1 未启动会话

`ready` 表示用户尚未启动仿真：

- 已安排任务显示 `pending`；
- 未安排任务显示 `unassigned`；
- 可用资源显示 `idle`，不可用资源显示 `unavailable`；
- 尚未包含在初始场景版本中的事件显示 `pending`。

开始运行后立即按当前仿真时刻和左闭右开规则投影。因此计划在 `window_start` 开始的零分钟移动任务，不会先产生虚假的 `en_route` 状态。

### 3.2 任务

对已安排任务按以下优先级判定：

1. `time >= service_ended_at`：`completed`；
2. `service_started_at <= time < service_ended_at`：`in_service`；
3. `travel_ended_at <= time < service_started_at`：`waiting`；
4. `travel_started_at <= time < travel_ended_at`：`en_route`；
5. 其他：`pending`。

任务在完成前保留任务起点，完成后定位到任务终点。`next_transition_at` 指向当前状态的下一个严格未来边界；无安排任务始终为 `unassigned`。

### 3.3 资源

资源状态优先级：

1. 场景标记不可用或不在 `[available_from, available_to)`：`unavailable`；
2. 当前任务的重新定位区间：`moving`；
3. 已到任务起点、服务尚未开始：`waiting`；
4. 服务区间：`serving`；
5. 其他可用时刻：`idle`。

资源位置只使用区域节点：

- `moving`：从上次位置到任务起点，显示重新定位进度；
- `waiting`：停在任务起点；
- `serving`：从任务起点到终点，显示服务进度；
- `idle/unavailable`：显示最近一次已完成任务的终点，尚无完成任务时使用场景初始位置。

零分钟重新定位没有 `moving` 区间。进度限制为 `0-100`，不生成经纬度或真实车辆轨迹。

### 3.4 航班

- 当前时间达到计划/预计离港时为 `departed`；
- 否则达到登机开始时为 `boarding`；
- 其他时刻保留所选场景版本中的 `scheduled/delayed` 状态；
- 预计离港时间和登机口来自持久化场景版本；
- `last_event_id` 只引用已包含在该版本中的最近事件，尚未应用事件不能改写航班。

### 3.5 事件

- 所选场景版本已经包含的事件显示 `resolved`，并携带准确 `scenario_version_after`；
- 未应用且当前时间早于 `occurred_at` 时为 `pending`；
- 未应用且当前时间达到 `occurred_at` 时为 `triggered`。

M4-2 的 `triggered` 只表示计划发生时刻已到，不应用事件、不增加场景版本、不暂停时钟。M4-3 才实现原子事件应用、自动暂停和重规划。

## 4. 下一边界

`clock.next_boundary_at` 从以下严格未来时刻中取最早值：

- 任务重新定位开始/结束、服务开始/结束；
- 资源可用时段开始/结束；
- 航班登机开始和离港；
- 尚未应用事件的计划发生时刻；
- 场景窗口终点。

`ready` 会话允许下一边界等于当前 `window_start`，表示启动后会立即发生状态变化。到达边界后的查询返回边界右侧状态，不同时属于两个状态。

## 5. 实施任务

1. 新增内部 `RuntimeProjectionSource` 和纯投影函数。
2. 为 SQLite 增加兼容旧库的投影依据列，并验证重开数据库后可恢复。
3. 创建会话时保存场景、方案、完整事件目录和事件版本证据。
4. 将投影结果和真正的 `next_boundary_at` 接入 `_build_snapshot()`。
5. 覆盖 ready、边界前、边界时刻、边界后一秒、零分钟移动、资源不可用、航班、事件、刷新一致性和重启恢复。
6. 真实 Uvicorn 验证快照随仿真时间变化，但 revision 与审计不因查询增加。

## 6. 明确不做

- 不应用定时事件或生成新场景版本；
- 不启动 CP-SAT 重规划；
- 不生成、采用或拒绝候选方案；
- 不写任务完成执行事实；
- 不实现 SSE、轮询恢复或前端控制条；
- 不改变 M4-0 冻结的公开请求/响应模型和安全声明。

## 7. 退出条件

- 四类投影均来自持久化输入和权威时间，不读取静态演示输出拼装结果；
- 所有左闭右开边界及零时长区间测试通过；
- 同一时刻重复查询结果一致，revision 和控制审计不变；
- 服务重启且 M3 方案仓库为空时，新建 M4-2 会话仍能恢复完整投影；
- M4-1 控制、并发、恢复和全量旧测试无回归；
- 文档明确 M4-2 仍不是事件自动重规划或前端实时化完成态。
