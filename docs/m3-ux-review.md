# M3 UX 检查点：先让用户看懂，再继续扩展接口

## 背景

在 M3-4 开始前复核现有展示页，发现用户第一次进入页面会先接触 FIFO、CP-SAT、P1、资源利用率和密集任务表，无法快速判断“这个系统正在帮我解决什么问题、我该先点哪里、系统建议了什么”。这会削弱项目的实际可用性，也容易让约束优化能力被误解为术语堆砌。

本检查点只调整信息呈现和交互引导：不改动 M2 调度逻辑、不在前端重算指标、不接入 AI，也不把仿真结果表述为真实运行指令。

## 已实施的可理解性模型

1. **结论优先**：默认打开“系统优化建议”，首屏给出是否推荐采用、紧急任务是否按时保障、还剩多少项人工处理和是否存在资源/时间冲突。
2. **三步使用路径**：明确“看原安排 → 看变化后 → 看系统建议”，普通用户无需理解算法即可完成对照。
3. **术语降级、能力保留**：
   - “扰动前 FIFO”改为“原保障安排”；
   - “事件后 FIFO”改为“航班变化后”；
   - “CP-SAT 优化”改为“系统优化建议”；
   - `P1/P2/P3` 改为“紧急/优先/常规”，并说明保障顺序；
   - 区域代码在任务表中显示为中文地点名。
4. **行动语言**：未分配任务明确为“需要人工处理”；校验结论改为“检查通过：没有发现资源或时间冲突”；资源利用率解释为临时插入任务的余量。
5. **专业信息按需展开**：算法、版本、可追溯依据和校验范围保留在可展开区域，既支持答辩复核，也不妨碍首次使用。
6. **解释不是模型文案**：页面明确说明每个建议都有资源、地点、服务时间和独立冲突检查作为依据；这些内容来自既有确定性计算结果。

## 边界与下一步

- 当前页面仍读取 M2 导出的合成演示数据；M3-6 再替换为 API 优先、静态回退。
- “查看系统建议”在当前页面切换演示视图；M3-4 将提供相同语义的结构化事件与计划创建 API，M3-6 再接到页面操作。
- 继续保留安全提示：**仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。**
