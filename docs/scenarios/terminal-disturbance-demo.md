# 东区登机口扰动演示场景

对应数据文件：`data/scenarios/terminal-disturbance-demo.json`

## 场景目的

在一个小时的仿真窗口内，展示两个航班同时受到运行扰动时，有限的轮椅、服务人员和摆渡车如何被结构化记录，为后续 FIFO 基线与约束优化提供固定输入。

## 初始状态

- `FL-SIM102` 计划 08:35 从 `GATE-E01` 出发，08:00 发生 25 分钟延误。
- `FL-SIM218` 计划 08:50 从 `GATE-W03` 出发，08:04 发生登机口切换事件，目标登机口为 `GATE-E01`。
- 服务任务只使用 `TASK-001` 至 `TASK-004` 等匿名 ID。
- 可用资源为 1 辆摆渡车、2 台轮椅和 2 名服务人员，全部从 `TRANSFER-DESK` 开始。

`flights` 和 `tasks` 表示扰动发生前的基线状态，`events` 表示按 `occurred_at` 注入的事件流。因此 `TASK-002`、`TASK-004` 仍指向原登机口；M2 的重规划逻辑需要在事件生效后更新关联任务，而不是在 M1 导入阶段静默改写原始数据。

## 预期验证点

1. 所有任务和资源都引用已定义的航班或区域。
2. 所有时间字段包含时区，并落在 `08:00—09:00` 仿真窗口内。
3. 延误事件必须带 `delay_minutes`；登机口变更事件必须带新旧登机口。
4. 任何重复 ID、未知关联对象或非法时间窗都应在导入阶段拒绝。

该场景显式标记为 `data_classification: synthetic`。`SIM102`、`SIM218` 是虚构编码，不代表任何真实机场、航班或旅客数据。
