# M6-5 方案问答相关性与四分区修复计划

## 1. 目标

修复方案解释中“不同问题得到近似统一回答”和四个解释重点没有独立职责的问题。每次请求必须绑定当前场景版本或运行 session/revision，先由后端从权威事实识别问题主题和被点名实体，再由确定性规则或可选 OpenAI-compatible 模型生成可追溯回答。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 固定响应契约

- 响应回显后端实际处理的 `focus` 和规范化 `question`。
- `question_answer` 先直接回答用户问题，状态只允许 `not_asked`、`answered` 或 `insufficient_evidence`，并公开所用 `FACT-*` 与后端匹配的实体 ID。
- `summary` 只说明方案整体状态及其与问题的关系。
- `tradeoffs` 只说明目标收益、代价和量化取舍，至少一项。
- `task_changes` 只说明具体任务、资源、服务时间或路线的当前安排及相对基线变化，至少一项。
- `manual_handling` 只说明人员需要核对、协调或决定的事项，至少一项。
- `recommended_next_step` 仍只能提出人工复核、采用、保留或重新规划建议，不能执行操作。
- 所有事实性 claim 只能引用本响应中的后端权威证据，继续固定 `requires_human_confirmation=true` 和 `modifies_plan=false`。

## 3. 问题 grounding 与模型边界

- 后端按当前上下文匹配任务、资源、航班、事件、区域和方案 ID，并识别利用率、等待时间、路线、任务变化、事件、约束、目标取舍和人工协调等主题。
- 被问题点名的实体事实优先进入最多 100 条证据，不能因默认排序截断而漏掉。
- 有问题时，直接回答和当前重点分区必须引用至少一条问题相关事实；只引用合法但无关的 `FACT-*` 仍视为模型输出无效并安全回退。
- 无相关权威事实时不调用模型，返回 `insufficient_evidence`；在 M6-5A 空间契约落地前，不猜测平面图位置、坐标、实时轨迹或现场状态。
- 模型只能改进表达和跨事实归纳，不能创造实体、坐标、事件、任务变化或指标，也不能修改方案、推进时钟、采用候选或绕过人工确认。

## 5. 验收场景

1. “当前方案总体资源利用率是多少，意味着什么？”直接引用总体利用率事实，回答数值及其可支持的有限含义。
2. 点名一个实际任务询问执行资源、服务时间和路线时，直接引用该任务分配事实；即使该任务不在默认前 20 条中也不能遗漏。
3. “哪些任务需要人工协调，为什么？”根据未安排任务、硬约束和方案状态回答；没有未安排任务时明确说明当前事实没有显示此类任务。
4. 两个主题不同的问题，其直接回答和当前重点分区在内容及证据上均不同。
5. 模型返回存在但与问题无关的证据 ID 时，响应回退确定性规则并标记非法模型输出。
6. 询问当前事实尚未提供的平面图坐标或实时位置时，明确说明证据不足，不调用模型、不编造。
7. 页面完整展示针对问题的回答、方案摘要、方案取舍、任务变化、人工处理和建议下一步，没有内部滚动区。

## 6. 禁止事项

- 不把用户问题、模型文字或前端状态提升为权威运行事实。
- 不接入未经授权的机场图、真实机场生产数据、个人信息或外部控制系统。
- 不把 API key、内部提示词、提供方原始错误或请求正文写入前端、日志、Git 或公开响应。
- 不改变既有 CP-SAT、独立硬约束校验、revision 并发保护、事件边界、候选确认和审计所有权。
- 不以本修复提前实现 M6-5A；只为未来 `SPATIAL-FACT-*` 接入保留可扩展问答边界。
