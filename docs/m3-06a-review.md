## 加载契约

`loadDemoPayload()` 返回 `{ payload, source }`，其中 `source` 只有两种取值：

| 来源 | 含义 | 请求顺序 |
| --- | --- | --- |
| `api` | `/api/v1/demo` 返回有效 `DemoPayload` | 第 1 次请求成功即结束 |
| `static_fallback` | API 不可用，静态演示文件返回有效数据 | 仅在 API 失败后请求 |

网络错误、非 2xx 响应、JSON 解析失败或基础契约缺失均视为该来源加载失败。两种来源都失败时抛出 `DemoPayloadLoadError`：页面只显示统一操作提示，错误对象仅保留来源、失败类别和可选 HTTP 状态，不包含原始响应、异常文本或本地路径。

静态请求附加 `reload` 参数并设置 `cache: "no-store"`。顶部刷新按钮和错误页“重新载入”按钮都会增加重试令牌，从 API 开始重新执行整条链；组件卸载或新一轮加载开始时会取消旧请求并阻止旧结果覆盖新状态。

## 实现与安全审查

1. `App.tsx` 不再直接调用 `fetch`，只通过 `loadDemoPayload()` 获取演示契约。
2. 加载器只做来源选择和最低限度的响应结构检查，不复制 FIFO、CP-SAT、比较指标或说明文案公式。
3. Vite 代理目标默认是 `http://127.0.0.1:8000`，可由 `VITE_API_TARGET` 覆盖；后端无需新增 CORS 通配配置。
4. API 和静态数据继续共用 `DemoPayload`，安全声明保持为：`仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。`
5. 当前 `App` 有意不保存或展示 `source`；M3-6B 将以同一返回值完成来源状态和五页联调，不再新增第二套加载逻辑。
