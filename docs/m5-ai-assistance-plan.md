# M5 AI 事件理解与结果解释实施计划

## 1. 阶段目标

M5 在 M4 已完成的后端权威实时系统上增加可替换的 AI 辅助层，用于自然语言事件理解、字段缺失追问、调度目标建议和基于权威事实的方案解释。AI 只降低结构化录入和理解成本，不拥有场景版本、运行 revision、仿真时间、任务/资源状态、当前方案或候选方案。

M5 完成后，用户可以输入“SIM102 刚确认延误 20 分钟”一类匿名教学文本，先看到结构化事件草稿与字段依据；信息不足时得到明确追问；人工确认后才进入现有事件应用和确定性重规划链。用户也可以对当前或候选方案请求解释，解释必须引用后端计划、指标、任务差异和约束事实。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 不可改变的状态所有权

| 事实 | 唯一所有者 | AI 允许做什么 | AI 禁止做什么 |
| --- | --- | --- | --- |
| 场景版本与事件目录 | 场景服务与版本仓库 | 提议结构化事件草稿 | 直接应用事件、绕过 `expected_version` |
| 运行时间与 revision | `RuntimeSessionService` 与 SQLite | 使用权威快照作为解释上下文 | 推进时间、修改 revision、创建第二状态机 |
| 当前/候选方案 | FIFO/CP-SAT、运行仓库 | 解释权威计划和真实差异 | 自由生成或静默替换方案 |
| 硬约束 | `validate_plan` | 引用违规为 0 或具体违规事实 | 宣称未经复核的方案可执行 |
| 用户决定 | 人工确认接口 | 给出待确认建议和下一步 | 自动采用候选、自动执行事件 |
| 前端 | M4 共享运行工作区 | 展示草稿、追问、解释和来源 | 保存平行业务状态或伪造实时变化 |

## 3. 实施单元

| 单元 | 工作内容 | 退出证据 | 状态 |
| --- | --- | --- | --- |
| M5-0 | 冻结事件草稿、追问、目标建议、方案解释、来源与回退契约 | Pydantic 契约、专项测试、契约文档 | 已完成（2026-08-05） |
| M5-1 | 实现确定性中文规则解析器和至少 10 条样例，无模型也可完成草稿/追问 | 延误、登机口变更、时间、航班和缺失字段测试 | 已完成（2026-08-05） |
| M5-2 | 接入可替换的 OpenAI-compatible 结构化输出适配器 | 超时、不可用、非法输出均回退规则解析；无密钥测试 | 已完成（2026-08-05） |
| M5-3 | 实现人工复核提交与确定性调度目标配置 | 事件仍走版本保护；目标经人工确认后才进入 CP-SAT | 已完成（2026-08-06） |
| M5-4 | 实现场景计划与运行当前/候选方案的事实化解释 | 每段结论引用后端事实 ID，陈旧 revision 拒绝解释 | 已完成（2026-08-06） |

执行顺序固定为 M5-0 至 M5-6。M5-0 至 M5-5 已完成，下一唯一入口为 M5-6。每个单元独立审查、验证和提交；不得以模型文案可用替代确定性业务闭环。

### M5-2 提供方决策

- 首个已授权提供方为 DeepSeek，通过 OpenAI-compatible HTTP 适配器接入；业务服务只依赖项目内提供方接口，不能把 DeepSeek SDK、模型名或响应结构扩散到解析器、API 路由和前端。
- `AI_API_KEY`、`AI_BASE_URL` 与 `AI_MODEL` 只从本地进程环境或忽略提交的本地配置读取。密钥不写源码、文档、测试、命令输出、日志、审计、前端或 API 响应。
- M5-2 自动化测试使用本地假提供方覆盖成功、未配置、超时、提供方错误和非法结构输出；外部实时调用不是回归测试前提。
- 即使模型调用成功，输出仍先经过 M5-0 Pydantic 契约、场景实体与 version/revision 核对；任一失败都回退 M5-1 规则，不能直接应用事件或触发规划。

### M5-3 人工提交与目标配置决策

- `POST /api/v1/assistant/event-drafts/submit` 不保存第二份服务器草稿；客户端必须回传完整 `EventDraftResponse` 并显式提交 `confirm_event=true`。
- 场景事件复用 `ScenarioService.apply_events()` 和 `expected_version`。运行事件复用 `RuntimeSessionService`、SQLite revision、权威仿真时间、既有事件边界和滚动重规划链，只允许在 `ready` 或 `paused` 提交。
- 运行提交还必须显式选择有限 `objective_profile` 并提交 `confirm_objective=true`。当前时刻事件立即进入既有候选链，未来事件只登记为新事实并在权威仿真时钟到达时触发；候选均不自动采用。
- 运行投影持久保存当前目标。事件候选被采用或保留后，后续自动事件和人工重规划继续使用该目标；重置恢复初始方案目标。旧 SQLite 投影缺少该字段时按 `balanced` 读取。
- 详细实现、兼容性修正和验证证据见 [m5-03-review.md](m5-03-review.md)。

### M5-4 权威方案事实与可追溯解释决策

- `POST /api/v1/assistant/plan-explanations` 只读支持场景方案和运行方案两种上下文；运行请求通过 `RuntimeSessionService.get_explanation_context()` 将 revision 绑定的快照和持久化投影事实作为同一读取边界，不能旁路读取旧 SQLite 场景版本。
- 后端按确定性顺序构造指标、目标、任务分配、未分配任务、硬约束、事件和方案差异事实。摘要、每项取舍和建议下一步都必须引用响应中的 `FACT-*` ID；模型不能创建事实或改变实体、时间、方案状态。
- 未配置 AI 时规则解释完整可用；模型只做表达增强。超时、网络错误、非法结构、未知 evidence ID 或不完整 claim 均回退规则解释；`deterministic_only` 保持零外部调用。
- 解释不会应用事件、创建候选、采用方案、推进仿真时间、写审计或增加 revision，响应固定要求人工确认并保留完整教学仿真安全声明。
- 外部调用继续使用 OpenAI-compatible HTTP 和 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 环境变量，不写入 GitHub、前端 bundle、日志或 API 响应；无 AI 配置时 GitHub 克隆和公网部署仍可运行核心闭环。
- 详细实现与验证见 [m5-04-review.md](m5-04-review.md)。

### M5-5 前端辅助交互决策

- “事件影响”页直接绑定共享 `RuntimeSessionSnapshot` 的 session 与 revision，支持缺失字段追问、逐字段来源、四选一调度目标和双重人工确认；提交成功后的快照继续由 `useRuntimeSession` 唯一接管，不建立第二时钟、第二规划器或第二运行状态。
- 输入内容、模式、目标选择、确认勾选和草稿仅保存在组件内存；输入或运行 revision 变化后旧草稿立即过期并禁止提交。事件进入权威链后生成的候选仍必须在既有方案页人工采用或保留。
- “方案依据”页支持当前方案与待确认候选、四种解释重点和匿名补充问题；解释绑定 session、revision、方案、基线、重点、问题与模式，任一条件变化后旧结果只供追溯，不自动重发请求，也不能触发方案采用。
- 页面展示规则/模型来源、事实摘要、取舍、建议和 `FACT-*` 引用。未配置模型时，追问、草稿、人工提交、确定性规划和事实解释均完整可用。
- 新区域按内容自然展开，不设置卡片内部纵向滚动；桌面和移动只使用整页工作区滚动。前端只调用同源 `/api/v1`，不包含密钥、提供方 URL、模型名或 DeepSeek 专用 SDK。
- 详细范围与验证见 [m5-05-plan.md](m5-05-plan.md) 和 [m5-05-review.md](m5-05-review.md)。

## 4. 事件理解流程

```text
匿名自然语言输入
  -> 解析请求绑定场景 version 或运行 session + revision
  -> 模型结构化抽取（可选）
  -> Pydantic 校验和场景实体核对
  -> 失败时确定性规则回退
  -> 字段不足：逐字段追问
  -> 字段完整：返回带依据的 FlightEvent 草稿
  -> 用户人工复核并确认有限调度目标（运行上下文）
  -> 提交接口核对 expected_version/revision、时间和实体
  -> 确定性 CP-SAT + 独立硬约束复核
  -> 候选方案继续等待人工采用或保留
```

模型响应、规则解析结果和用户输入都不直接修改状态。事件 ID 由后端生成；相对时间只能用请求绑定的权威参考时间解释；航班、登机口和场景版本必须在服务层核对。

## 5. 无模型与故障回退

- 默认 `auto` 模式：配置模型时先尝试结构化调用；未配置、超时、提供方错误或输出未通过契约时，自动进入确定性规则解析。
- `deterministic_only` 模式：完全不发起外部模型请求，用于离线演示、自动化测试和故障隔离。
- 回退响应明确显示 `source`、是否尝试提供方和安全的 `fallback_reason`，但不返回密钥、URL、原始异常或内部提示词。
- 规则也无法理解时返回 `unsupported` 或 `needs_clarification`，不猜测事件、不伪造字段。
- AI 不可用不能影响 M4 运行、计划查询、事件应用、重规划、SSE 或人工确认。

## 6. 调度目标边界

M5 只允许四个有限、可测试的目标配置：均衡、关键任务优先、最小等待、最小变更。自然语言只能产生 `ObjectiveRecommendation`，且固定标记 `applied_to_planner=false`。M5-3 已要求由用户确认后才把枚举配置传给确定性优化器；模型不得提供任意权重、目标函数代码或直接排班结果。

`balanced` 精确保留 M4 原词典序：先保护 P1 关键任务，再最大化已安排任务数和优先级得分，最后降低等待、移动和资源排序成本。`critical_first` 在 P1 之后先最大化优先级得分；`minimum_wait` 在 P1 和任务覆盖不降低的前提下先减少总等待；`minimum_change` 只在有当前执行方案的滚动规划中优先保留未来任务的资源安排。旧 CP-SAT 请求未显式选择目标时仍使用 `balanced`；显式目标一律要求确认，所有候选继续通过独立硬约束复核。

## 7. 方案解释边界

- 解释请求绑定不可变场景版本，或绑定运行 session、revision 和具体方案 ID。
- 后端先构造有限的 `ExplanationEvidence`，包括指标、任务分配、未安排原因、约束、事件和计划差异。
- 模型或规则只组织这些事实；摘要、每项取舍和下一步均为独立 `ExplanationClaim`，每条 claim 引用的 evidence ID 必须存在，不允许引用自由生成的来源。
- 陈旧 revision、方案不存在或方案不属于上下文时，服务拒绝请求，而不是解释其他方案。
- 解释固定 `modifies_plan=false`、`requires_human_confirmation=true`，不能成为采用候选的隐式命令。

## 8. 数据与安全

- 只处理匿名化、历史回放或合成教学数据；输入组件明确禁止姓名、证件号、联系方式等个人信息。
- 默认不持久化原始自然语言、模型提示词或模型完整响应；审计只记录草稿/解释 ID、场景或会话 ID、来源、结果状态和安全错误码。
- 密钥只从本地环境变量或后续安全配置读取，不写入仓库、前端、日志、审计或 API 响应。
- 外部模型输入使用最小必要事实，不发送整库、SQLite 文件、审计历史、本机路径或其他会话数据。
- 提示词注入、越权指令或要求直接执行操作只作为普通不可信文本处理，不能改变工具、路由或状态所有权。
