# M5 AI 事件理解与结果解释实施计划

## 1. 阶段目标

M5 在 M4 已完成的后端权威实时系统上增加可替换的 AI 辅助层，用于自然语言事件理解、字段缺失追问、调度目标建议和基于权威事实的方案解释。AI 只降低结构化录入和理解成本，不拥有场景版本、运行 revision、仿真时间、任务/资源状态、当前方案或候选方案。

M5 完成后，用户可以输入“SIM102 刚确认延误 20 分钟”一类匿名教学文本，先看到结构化事件草稿与字段依据；信息不足时得到明确追问；人工确认后才进入现有事件应用和确定性重规划链。用户也可以对当前或候选方案请求解释，解释必须引用后端计划、指标、任务差异和约束事实。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 不可改变的状态所有权

| 事实 | 唯一所有者 | AI 允许做什么 | AI 禁止做什么 |
| --- | --- | --- | --- |
| 场景版本与事件目录 | 场景服务与版本仓库 | 提议结构化事件草稿 | 直接应用事件、绕过 `expected_version` |
| 运行时间与 revision | `RuntimeSessionService` 与 SQLite | 使用权威快照作为解释上下文 | 推进时间、修改 revision、创建第二状态机 |
| 当前/候选方案 | FIFO/CP-SAT、运行仓库 | 解释权威计划和真实差异 | 自由生成或静默替换方案 |
| 硬约束 | `validate_plan` | 引用违规为 0 或具体违规事实 | 宣称未经复核的方案可执行 |
| 用户决定 | 人工确认接口 | 给出待确认建议和下一步 | 自动采用候选、自动执行事件 |
| 前端 | M4 共享运行工作区 | 展示草稿、追问、解释和来源 | 保存平行业务状态或伪造实时变化 |

## 3. 实施单元

| 单元 | 工作内容 | 退出证据 | 状态 |
| --- | --- | --- | --- |
| M5-0 | 冻结事件草稿、追问、目标建议、方案解释、来源与回退契约 | Pydantic 契约、专项测试、契约文档 | 已完成（2026-08-05） |
| M5-1 | 实现确定性中文规则解析器和至少 10 条样例，无模型也可完成草稿/追问 | 延误、登机口变更、时间、航班和缺失字段测试 | 已完成（2026-08-05） |
| M5-2 | 接入可替换的 OpenAI-compatible 结构化输出适配器 | 超时、不可用、非法输出均回退规则解析；无密钥测试 | 已完成（2026-08-05） |
| M5-3 | 实现人工复核提交与确定性调度目标配置 | 事件仍走版本保护；目标经人工确认后才进入 CP-SAT | 待开始 |
| M5-4 | 实现场景计划与运行当前/候选方案的事实化解释 | 每段结论引用后端事实 ID，陈旧 revision 拒绝解释 | 待开始 |
| M5-5 | 在事件页和方案页接入辅助交互 | 桌面/移动可追问、复核、提交和查看依据，不增加第二运行状态 | 待开始 |
| M5-6 | 完成模型/无模型、故障、注入防护、浏览器和三轮总验收 | M5 硬性退出条件全部通过 | 待开始 |

执行顺序固定为 M5-0 至 M5-6。M5-0 至 M5-2 已完成，下一唯一入口为 M5-3。每个单元独立审查、验证和提交；不得以模型文案可用替代确定性业务闭环。

### M5-2 提供方决策

- 首个已授权提供方为 DeepSeek，通过 OpenAI-compatible HTTP 适配器接入；业务服务只依赖项目内提供方接口，不能把 DeepSeek SDK、模型名或响应结构扩散到解析器、API 路由和前端。
- `AI_API_KEY`、`AI_BASE_URL` 与 `AI_MODEL` 只从本地进程环境或忽略提交的本地配置读取。密钥不写源码、文档、测试、命令输出、日志、审计、前端或 API 响应。
- M5-2 自动化测试使用本地假提供方覆盖成功、未配置、超时、提供方错误和非法结构输出；外部实时调用不是回归测试前提。
- 即使模型调用成功，输出仍先经过 M5-0 Pydantic 契约、场景实体与 version/revision 核对；任一失败都回退 M5-1 规则，不能直接应用事件或触发规划。

## 4. 事件理解流程

```text
匿名自然语言输入
  -> 解析请求绑定场景 version 或运行 session + revision
  -> 模型结构化抽取（可选）
  -> Pydantic 校验和场景实体核对
  -> 失败时确定性规则回退
  -> 字段不足：逐字段追问
  -> 字段完整：返回带依据的 FlightEvent 草稿
  -> 用户人工复核
  -> 既有事件应用接口核对 expected_version/revision
  -> 确定性 CP-SAT + 独立硬约束复核
  -> 候选方案继续等待人工采用或保留
```

模型响应、规则解析结果和用户输入都不直接修改状态。事件 ID 由后端生成；相对时间只能用请求绑定的权威参考时间解释；航班、登机口和场景版本必须在服务层核对。

## 5. 无模型与故障回退

- 默认 `auto` 模式：配置模型时先尝试结构化调用；未配置、超时、提供方错误或输出未通过契约时，自动进入确定性规则解析。
- `deterministic_only` 模式：完全不发起外部模型请求，用于离线演示、自动化测试和故障隔离。
- 回退响应明确显示 `source`、是否尝试提供方和安全的 `fallback_reason`，但不返回密钥、URL、原始异常或内部提示词。
- 规则也无法理解时返回 `unsupported` 或 `needs_clarification`，不猜测事件、不伪造字段。
- AI 不可用不能影响 M4 运行、计划查询、事件应用、重规划、SSE 或人工确认。

## 6. 调度目标边界

M5 只允许四个有限、可测试的目标配置：均衡、关键任务优先、最小等待、最小变更。自然语言只能产生 `ObjectiveRecommendation`，且固定标记 `applied_to_planner=false`。M5-3 必须由用户确认后，将枚举配置传给确定性优化器；模型不得提供任意权重、目标函数代码或直接排班结果。

当前 M4 的默认词典序目标继续作为 `balanced` 基线：先最大化已安排任务数，再优先高优先级任务，最后降低等待、移动和资源排序成本。其他配置必须通过独立测试证明硬约束不变后才能开放。

## 7. 方案解释边界

- 解释请求绑定不可变场景版本，或绑定运行 session、revision 和具体方案 ID。
- 后端先构造有限的 `ExplanationEvidence`，包括指标、任务分配、未安排原因、约束、事件和计划差异。
- 模型或规则只组织这些事实；摘要、每项取舍和下一步均为独立 `ExplanationClaim`，每条 claim 引用的 evidence ID 必须存在，不允许引用自由生成的来源。
- 陈旧 revision、方案不存在或方案不属于上下文时，服务拒绝请求，而不是解释其他方案。
- 解释固定 `modifies_plan=false`、`requires_human_confirmation=true`，不能成为采用候选的隐式命令。

## 8. 数据与安全

- 只处理匿名化、历史回放或合成教学数据；输入组件明确禁止姓名、证件号、联系方式等个人信息。
- 默认不持久化原始自然语言、模型提示词或模型完整响应；审计只记录草稿/解释 ID、场景或会话 ID、来源、结果状态和安全错误码。
- 密钥只从本地环境变量或后续安全配置读取，不写入仓库、前端、日志、审计或 API 响应。
- 外部模型输入使用最小必要事实，不发送整库、SQLite 文件、审计历史、本机路径或其他会话数据。
- 提示词注入、越权指令或要求直接执行操作只作为普通不可信文本处理，不能改变工具、路由或状态所有权。

## 9. M5 硬性退出条件

- [x] 至少 10 条自然语言事件样例覆盖完整、缺失、歧义和不支持输入。
- [x] 事件草稿经过 Pydantic 与场景实体校验，并显示逐字段依据。
- [x] 字段不足时逐项追问，不猜测航班、时间、延误分钟或登机口。
- [x] 未配置模型、超时、提供方错误和非法输出均可靠回退，M4 核心闭环不受影响。
- [ ] 目标建议必须人工确认，且只使用有限确定性枚举。
- [ ] 方案解释只引用当前权威版本/revision 的后端事实。
- [ ] AI 不直接应用事件、生成自由排班、采用候选或修改运行状态。
- [ ] 桌面和移动端可完成输入、追问、复核和解释流程，无内部敏感信息泄露。
- [ ] 所有界面和响应保留完整安全声明，不暗示真实机场生产控制能力。
