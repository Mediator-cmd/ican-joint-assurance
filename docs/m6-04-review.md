# M6-4 大数据相关 API 与五页工作台体验收敛审查

## 1. 结论

M6-4 已完成。现有五页运行工作台继续共享唯一 `RuntimeSessionSnapshot`，后端在同一快照上公开严格派生的集合摘要，前端通过搜索、分页和移动端卡片控制 DOM 规模。没有新增第二业务状态、第二时钟、第二规划器或平行 API 状态，也没有修改 M6-3 冻结场景、样本和正式报告。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 后端权威集合摘要

`RuntimeCollectionSummary` 随 `RuntimeSessionSnapshot` 的 REST 响应和 SSE 完整快照一起序列化，字段覆盖：

- 任务总数、活动任务、需关注任务、完成任务和锁定任务；
- 资源总数和活动资源；
- 事件总数、开放事件和待发生事件；
- 航班总数。

所有字段均为非负整数，子计数不能超过对应总数，事件满足 `pending <= open <= total`。摘要直接从快照内任务、资源、事件和航班投影计算，不持久化第二份计数，也不接受前端上传。

## 3. 前端有界数据视窗

任务、资源、事件、航班和区域均可按当前权威快照检索，并分别以 50、40、20、24、20 项为页面窗口。受影响任务每页 30 项；每个当前/候选方案列独立显示 25 项任务书；候选差异每页 20 项。分页条始终展示当前范围、总数、当前页和总页数，空集合稳定显示 `0–0 / 共 0 项`。

检索、筛选、页码和选中项只是 React 展示状态，不调用写 API、规划器或 AI，不推进仿真时间，也不增加 revision。从资源衔接或受影响任务跳转时，页面会清除冲突任务检索、切回全部任务并定位目标所在页。

工作台统计改为读取后端 `collection_summary`。AI 仍只负责匿名事件抽取和权威事实表达增强，不能生成摘要、分页、计划或自动候选决定。

## 4. 加载、恢复和响应式体验

- 初始化界面依次说明“载入匿名教学场景、恢复 SQLite 运行会话、建立权威状态流”，不伪造进度百分比。
- 连接提示同时提供“读取权威快照”和“重新连接”；revision 冲突仍只刷新，不自动重放旧命令。
- 任务表在 520 像素以下变为带字段标签的卡片；资源行在移动端变为两列卡片，取消内部横向滚动。
- 任务书、候选变化、受影响任务和其他分页列表按内容自然展开，不使用列表内部纵向滚动。方案页继续完整展示中文算法、用途、资源、时段、路线和指标，方案 ID 只是次级审计信息。
