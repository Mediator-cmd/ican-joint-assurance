# M4-5 计划：五页实时运行工作台

## 1. 目标

把现有由 `/api/v1/demo` 加载三套固定快照的五页工作台，升级为直接消费后端权威 `RuntimeSessionSnapshot` 的教学仿真实时运行界面。用户无需刷新页面即可看到仿真时间、任务、资源、航班、事件和候选方案随后端状态演进，并可明确执行开始、暂停、倍速、重置、手动重规划以及候选采用或保留。

本单元完成后，正常在线流程不再以固定快照切换作为主要体验。静态 `demo-output.json` 只保留为服务不可用时的离线只读说明页。

所有运行界面继续完整显示：

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 当前基线

- M4-1 至 M4-4 已提供 SQLite 运行会话、后端权威时钟、确定性状态投影、事件自动应用、滚动重规划、候选人工确认、类型化 SSE、256 条缓冲和 REST 轮询恢复。
- 前端仍只持有 `DemoPayload` 和 `baseline / after_events_fifo / optimized` 三套固定视图。
- `/api/v1/demo` 及静态 JSON 继续提供场景说明和离线展示，但不再承担在线运行状态。
- 现有五页、选择联动、大字号可读性层、Vite `/api` 代理、Edge 优先启动和精确停止边界全部保留。

## 3. 状态所有权

| 状态 | 唯一所有者 | 前端职责 |
| --- | --- | --- |
| 仿真时间、倍速、是否推进 | 后端运行会话 | 原样显示；`runtime.tick` 只替换后端 clock |
| 会话状态、revision、场景版本 | SQLite 权威会话 | 显示并在控制请求中提交当前 revision |
| 当前方案与候选方案 | 后端运行聚合 | 展示差异并提交采用或保留命令 |
| 任务、资源、航班、事件状态 | 后端确定性投影 | 按枚举和后端中文标签呈现，不自行推导 |
| SSE stream ID 与 sequence | 当前后端生命周期 | 客户端仅保存最后已处理游标并去重 |
| 连接状态与轮询生命周期 | 浏览器 | 显示在线、恢复中、轮询恢复或离线只读 |
| 当前工作页、筛选与实体选择 | 浏览器 | 五页共享，快照变化后只协调失效选择 |
| 调度、硬约束和事件应用 | 后端确定性服务 | 不在浏览器复制或触发隐式计算 |

五页必须共享同一份 `RuntimeSessionSnapshot`、连接状态和选择状态。不得为任一页面创建独立时钟、独立运行快照或独立控制链。

## 4. 在线启动与会话恢复

在线启动采用固定顺序：

1. 读取 `/api/v1/demo`，取得项目说明及初始场景 V1；失败后才读取静态 JSON。
2. 若数据来自 API，查询该初始场景版本的 CP-SAT 方案；不存在时通过现有计划 API 生成一次。
3. 按场景 ID 查询 SQLite 运行会话，列表按最近更新时间返回。
4. 逐个读取候选会话的完整快照，只复用 `initial_scenario_version` 与优化初始方案一致的最近会话。
5. 没有匹配会话时才创建；页面刷新、切页、筛选和 SSE 重连不得创建新会话。
6. 找回或创建成功后，以 REST 完整快照建立前端基线，再连接 SSE。

M3 场景和普通方案仍是进程内数据。服务重启后若已有 SQLite 会话，必须优先使用其持久化投影，不要求重新生成相同的进程内方案才能查看或继续会话。

## 5. SSE 与恢复状态机

- 首个 `runtime.snapshot` 原子替换完整快照。
- `runtime.tick` 只替换 snapshot 中的后端 clock，不自行改变 revision、状态或投影。
- 其他类型化消息用于即时提示；业务显示最终仍以随后到达的完整 snapshot 为准。
- 客户端按 `stream_id + sequence` 去重；不能用 revision 过滤 tick 或 heartbeat。
- SSE 异常先自动重连。连续失败后进入恢复状态，并每 2 秒读取 `GET /runtime-sessions/{session_id}`。
- REST 轮询成功即原子替换快照；SSE 恢复并收到可用消息后停止轮询。
- 组件卸载、会话切换或离线降级时必须关闭 EventSource 和轮询定时器。
- 连接状态固定为：`connecting`、`live`、`recovering`、`polling`、`offline_readonly`。

## 6. 控制与并发

- 开始、暂停、倍速、重置、手动重规划、候选采用和保留均调用现有 REST 路径。
- 所有修改命令携带当前 `expected_revision`；候选决定同时携带当前 `candidate_plan_id`。
- `409 runtime_revision_conflict`、`runtime_invalid_transition` 或 `runtime_candidate_mismatch` 后，先重新读取权威快照，再显示安全提示；不得自动重放可能已过期的命令。
- 控制请求进行中禁用同类操作，防止重复点击；响应成功后用返回的完整快照原子更新。
- 重置必须有明确确认，不允许单击误触。

## 7. 五页用户流程

### 7.1 统一控制条

始终显示仿真时间、会话状态、开始/暂停、`1x / 5x / 15x`、连接状态、场景版本、重置和合适的手动重规划入口。用户不需要理解 SSE、revision 或 CP-SAT。

### 7.2 调度总览

直接回答“现在发生什么、系统正在做什么、需要我决定什么”，并展示任务状态分布、当前活动资源、下一业务边界和待确认候选。

### 7.3 任务计划

按实时状态筛选和组织任务，显示当前资源、当前位置、下一转换时间、受影响事件和锁定事实。切换筛选或查看详情不得触发规划。

### 7.4 事件影响

以处理时间流展示等待发生、已触发、已应用、重规划中、方案待确认、处理完成或失败，并同时显示航班预计时间、登机口和最近事件。

### 7.5 资源态势

展示空闲、移动、等待、服务中和不可用状态，以及区域间移动进度、当前/下一任务和下一可用时间。没有经纬度事实时不绘制真实轨迹。

### 7.6 方案依据

显示当前执行方案、待确认候选、场景版本、revision、独立约束语义和明确的“采用候选”“保留当前方案”操作。候选确认前绝不替换 active plan。

## 8. 非循环与后续扩展约束

- 运行从窗口起点单向推进到完成，不自动回到起点循环播放。
- 任务或资源可以在真实持续区间保持同一状态；只有到达后端业务边界时才变化，不制造随机跳数。
- 同一事件在同一会话只应用一次，状态不得倒退，完成后保持完成，除非用户明确重置。
- M4-5 不新增随机场景生成器。后续可通过带来源和种子的场景模板生成不同事件组合，但仍必须可复现、可审计。
- 后续 AI 可以解析新状况、生成待确认结构化事件、解释候选和提示风险；确定性规划、硬约束复核和人工确认边界不得被替代。

## 9. 离线只读

- `/api/v1/demo` 失败但静态 JSON 可用时，页面明确显示“离线演示，时间不会推进”。
- 离线模式保留五页查看能力和完整安全声明，但所有运行控制禁用。
- 不显示“实时在线”、不启动本地计时器、不伪造任务或资源变化。
- API 与静态文件均失败时保持现有可重试错误页。

## 12. 非目标

- 不接入真实机场生产数据、消息总线或控制系统。
- 不实现多 worker、分布式流、跨进程 SSE 补发或 PostgreSQL。
- 不在前端重算仿真时间、状态、事件、指标或方案。
- 不实现 AI 事件解析、随机场景生成、长时性能测试或三轮总验收；这些分别属于后续阶段。
- 不提前宣称完成 M4-6 或整个 M4。

1. 冻结本计划。
2. 增加运行类型、API 客户端、会话启动与恢复测试。

4. 接入统一运行控制条和并发冲突恢复。
5. 将权威投影映射到五页并完成候选决策。
6. 完成离线只读与响应式样式。
7. 执行前后端全量自动化和真实双服务浏览器验收。
8. 编写 review，更新持续交接和 README，独立提交 M4-5。
