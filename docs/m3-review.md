## 3. 可复核业务闭环

不依赖前端或自然语言 AI，API 已能完成：

```text
导入/查询场景
  -> 版本 1 生成 FIFO 原规则方案
  -> 携带 expected_version 应用结构化事件
  -> 从不可变基线重放事件并生成版本 2
  -> 版本 2 生成 CP-SAT 系统优化建议
  -> 独立硬约束复核
  -> 比较两套已保存方案
  -> 查询方案与审计记录
```

内置场景的稳定对比为：

| 指标 | FIFO 原规则方案 | CP-SAT 系统优化建议 | 变化 |
| --- | ---: | ---: | ---: |
| 已安排任务 | 4/5 | 5/5 | +1 |
| 紧急任务完成率 | 50% | 100% | +50 个百分点 |
| 待协调任务 | 1 | 0 | -1 |
| 硬约束违规 | 0 | 0 | 0 |

比较只读取已保存方案并新增审计记录，不覆盖场景、计划或历史版本。M3 响应以 `requires_human_confirmation: true` 明确提示建议不能直接执行，但尚未提供确认接口或运行状态切换；实际人工确认闭环属于 M4。

## 4. 契约与一致性保证

### 4.1 场景和事件

- 导入场景经过 Pydantic 严格校验，拒绝未知字段、非法时间和无效跨实体引用。
- 导入事件先进入独立待处理目录，不提前修改版本 1 基线。
- 每次事件修订从不可变基线重放全部已确认事件，避免延误重复累计。
- 事件应用和计划创建等依赖场景版本的写操作携带 `expected_version`；过期请求返回 `409` 且不写入部分状态。方案比较只校验两套已保存方案的归属和差异，不使用场景版本写入参数。

### 4.2 计划和比较

- FIFO 与 CP-SAT 共享同一场景模型、路径数据、指标模型和独立约束检查器。
- 计划保存前再次检查资源类型、容量、时间窗、路线和任务覆盖。
- 同一场景版本和算法只创建一套计划；已保存计划不可修改。
- 方案差值固定为“候选减基线”，并保留两侧完整指标快照。

### 4.3 错误和审计

- 公开错误统一返回 `code`、安全 `message`、字段位置和 `request_id`。
- 500 响应与服务日志不记录原始异常文本或本机路径，只保留请求 ID 和异常类型。
- 审计接口只公开动作、版本、匿名实体 ID 和安全摘要，不包含个人信息或原始请求。

## 5. 前端与本地运行

- `loadDemoPayload()` 是唯一演示载荷入口，按 API → 静态 JSON 顺序加载。
- 五页工作台共享同一载荷、方案选择和任务/事件/资源选择状态。
- 页面明确显示“服务数据”或“本地演示数据”，静态回退不伪装成服务在线。
- 根目录脚本将 FastAPI 和 Vite 作为一个服务组管理，后端健康后才启动前端。
- 停止脚本依据状态文件、项目路径、PID、进程名和启动时间精确停止，不批量结束其他 Python/Node 进程。

## 8. 已知边界

1. M3 仓库是进程内存储，服务重启后恢复内置基线；SQLite 持久化属于 M4。
2. 当前前端一次加载三套方案快照，不会自动推进仿真时间；M3 只有人工确认提示字段，没有确认接口和运行状态转换；动态运行硬性计划见 `m4-realtime-operations-plan.md`。
3. 自然语言事件理解和结果生成式解释属于 M5；核心调度不依赖 AI。
4. 真实机场数据接入需要授权、脱敏和接口适配，不是比赛 MVP 前置条件。
5. GitHub CLI 已登录，但远程仓库仍待名称确认，本阶段只形成可追溯本地提交。
