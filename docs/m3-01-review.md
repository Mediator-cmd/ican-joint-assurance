# M3-0/1 审查记录：契约冻结与 API 骨架

## 审查范围

- M3 API 契约与 M2 模型的兼容性。
- FastAPI 应用工厂、健康检查、OpenAPI 和请求 ID。
- 404、422、业务异常和未预期 500 的统一错误响应。
- 新增依赖、自动化测试和真实 Uvicorn HTTP 冒烟。

## 功能审查

| 检查项 | 结论 | 证据 |
| --- | --- | --- |
| M3-0 契约冻结 | 通过 | 端点、状态码、版本与事件语义已记录在 `m3-plan.md` |
| 健康检查 | 通过 | `GET /api/v1/health` 返回版本化 200 响应 |
| OpenAPI | 通过 | `/api/v1/openapi.json` 包含健康路由和统一错误模型 |
| 统一错误 | 通过 | 404、422、业务 409、未预期 500 均返回 `ApiErrorResponse` |
| 请求追踪 | 通过 | 成功与失败响应均带 `X-Request-ID`；错误体与响应头一致 |
| 错误脱敏 | 通过 | 500 响应不暴露异常原文；日志只记录请求 ID 和异常类型 |
| M2 回归 | 通过 | 原有 19 项与新增 6 项合计 `25 passed` |

## 审查中发现并解决的问题

1. FastAPI 0.140.7 使用的 Starlette 1.3.1 已将旧 `httpx` 测试客户端标记为弃用。根据本地依赖源码和 PyPI 可用版本，将项目测试依赖改为 `httpx2>=2,<3`，弃用警告消失。
2. 初版未预期异常日志包含完整异常原文，可能暴露本地路径。日志已收敛为请求 ID 与异常类型，并增加 `caplog` 断言防止回归。
3. 初版统一错误模型只存在于运行时响应，OpenAPI 中不明确。已为版本化路由登记 400、404、409、422、500 的 `ApiErrorResponse`。

## 剩余边界

- 当前仅有系统健康接口，没有场景、事件、计划或审计业务数据。
- 当前 `.runtime/server-state.json` 仍是单前端进程格式；双服务启停属于 M3-7。
- 当前网站继续读取静态 `demo-output.json`；API 优先和离线回退属于 M3-6。
- 内存仓库、场景版本和审计模型必须在 M3-2 完成后，才能安全开发场景路由。

## 审查结论

未发现阻塞 M3-0/1 提交的问题。下一执行单元固定为 M3-2，保持 M2 调度函数不依赖 FastAPI，并先用单元测试证明基线不可变、版本冲突不写入和审计顺序稳定。
