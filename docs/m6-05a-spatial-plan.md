# M6-5A 机场空间态势实施计划

## 目标

在现有五页实时工作台中加入原创匿名 2D 航站楼空间态势，将同一 `RuntimeSessionSnapshot` 中的事件、任务、资源、当前方案和待确认候选一一映射到空间对象。地图只展示后端已经核验的事实，不拥有时钟、事件、方案或人工决定。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 子阶段

| 子阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| M6-5A-0 | `SpatialLayout`、`RuntimeSpatialView`、原创 SVG、revision 绑定 API、`SPATIAL-FACT-*` 基础事实 | 默认场景的每个任务、资源、事件均有唯一投影；当前/候选路线只引用合法区域和路径；陈旧 revision 拒绝 |
| M6-5A-1 | 调度总览 2D SVG 态势图、图层开关、共享选择和资源进度渲染 | SSE/REST 快照变化后地图与任务列表同 revision；暂停不移动；候选虚线不覆盖当前实线；390px 无横向溢出 |
| M6-5A-2 | 空间 AI 问答与地图聚焦 | 绑定 session/revision/选择；回答只引用 `SPATIAL-FACT-*`；模型失败规则回退；未知位置不猜测 |
| M6-5A-3 | 六条一次性事件连续演示、断线/重启/采用/拒绝和多视口验收 | 每个事件产生可核对的空间变化；不存在循环、随机运动、第二状态机或旧回答冒充当前事实 |

## 空间事实边界

- 第一版使用本地原创 SVG，不导入北京大兴机场图片、商业地图、内部运行图、真实坐标或生产数据。
- 坐标使用 0-1 规范化本地坐标；几何路径与调度 `travel_minutes` 是两类事实，不能互相推导。
- `RuntimeSpatialView` 由后端从 `RuntimeProjectionSource`、运行快照和当前/候选 `Plan` 派生，按 `expected_revision` 读取；前端只绘制点、线和状态。
- 资源位置由后端 `from_zone_id/to_zone_id/progress_pct` 插值到空间路径；暂停、断线和加载旧视图时不自推进。
- 任务覆盖以 `(task_id, route_kind)` 唯一，资源和事件分别以自身 ID 唯一；未安排任务也必须显示为“待协调需求”，不能从地图消失。
- 当前方案使用实线，候选只显示相对当前方案发生变化的虚线；候选未人工采用前不能替换当前路线。
- AI 只读、必须人工确认，不能应用事件、采用候选、推进时钟、修改 revision 或发出真实运行控制指令。

## API 入口

`GET /api/v1/runtime-sessions/{session_id}/spatial?expected_revision=N` 返回布局、overlay、覆盖率和 `SPATIAL-FACT-*`。revision 不一致返回 409；不支持空间布局的规模场景返回明确的 `spatial_layout_not_available`，不随机摆放。

## 禁止事项

- 不建立地图专用时钟、随机资源动画、循环事件、前端规划器或第二份运行快照。
- 不使用 AI 文本猜测坐标、路线、楼层、现场进度或未提供的区域。
- 不把空间视觉近似描述为真实机场生产接入；GitHub/公网发布仍只包含匿名教学仿真。
