# M5-5 前端辅助交互接入审查

## 1. 结论

M5-5 已完成。事件草稿、缺失追问、人工复核提交、有限调度目标和方案事实解释已接入现有五页实时工作台；前端没有建立第二套运行状态，也没有把 AI 变成事件执行器或排班器。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 事件辅助交互

- “事件影响”页支持匿名教学文本与 `auto`、`deterministic_only` 两种模式；请求只提交当前 session、revision、原始文本和辅助模式，仿真时间、场景版本与当前登机口继续由后端权威上下文提供。
- 缺失字段按服务端追问逐项展示，可选规范值只追加到原输入；完整草稿展示事件类型、航班、发生时间、扰动字段和逐字段来源。
- 草稿与标准化输入、session 和 revision 绑定。输入变化或运行 revision 更新后旧草稿立即标记过期，即使人工确认仍保持提交禁用。
- 运行事件提交前必须分别确认事件字段和四选一确定性目标；提交复用既有 M5-3 接口，成功快照通过 `useRuntimeSession.commitSnapshot` 进入唯一共享状态。
- 草稿不会自动提交，事件产生的候选不会自动采用；候选继续在原方案页等待明确“采用候选”或“保留当前方案”。

## 3. 方案事实解释

- “方案依据”页可选择当前执行方案或待确认候选，以及方案摘要、方案取舍、任务变化和人工处理四种重点，并可附带匿名补充问题。
- 候选解释自动把当前方案作为基线。请求签名包含 session、revision、目标方案、基线方案、重点、问题和辅助模式；任何条件变化后旧解释只供追溯，不自动重发。
- 页面展示摘要、取舍、建议下一步及其引用的 `FACT-*` 权威事实，同时公开模型/规则来源和安全回退原因。解释固定只读，不能成为采用候选的隐式命令。
- 新板块按内容自然展开；事件目录、航班投影、方案任务书和解释结果均不设置内部纵向滚动条，整页工作区承担必要的页面滚动。

## 6. 安全、部署与下一入口

前端只调用同源 `/api/v1`，不读取、配置或回显 AI 环境变量；API key、提供方 URL 与模型名仍只属于后端进程环境。用户提供的真实密钥未写入源码、文档、测试、命令、日志、响应、前端 bundle 或 Git 历史。

M5-5 继续只使用匿名合成教学数据，不接真实机场生产数据、个人信息或外部控制系统。AI 只辅助事件理解和事实表达；Pydantic、权威 version/revision、CP-SAT、独立硬约束复核和人工确认仍是业务闭环。

M5-6 是下一唯一入口，负责模型/无模型、提供方故障、提示词注入、浏览器和三轮连续总验收。本单元不进入 M6，不创建 GitHub 远程仓库，不推送代码，不发布公网地址。
