# M6-0 规模与部署契约审查

## 1. 结论

M6-0 已完成。M6 的三个规范规模档位、性能计时口径、基准样本/报告、有限回退原因、零硬约束违规要求和部署安全边界已经冻结并通过自动化验证。

本单元没有生成 100/500/2000 任务场景，没有运行或修改规模调度算法，也没有创建容器、GitHub 远程或公网部署。当前不能声称 M6 性能目标已经达成；实际数据从 M6-1 场景工厂和 M6-3 基准报告开始产生。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 冻结内容

- `small` 固定为 100 任务、20 资源、5 区域和 2 秒目标；`medium` 固定为 500/50/10 和 5 秒；`large_aggregate` 固定为 2000/200/20 和 15 秒。
- 小型和中型档位只接受实际 CP-SAT 路径；大型聚合档位可接受明确标记 `model_size_guard` 或 `time_limit` 的确定性安全回退。
- 每个样本必须覆盖全部任务，计划不得为 `invalid`，硬约束违规固定为 0。部分方案必须如实记录待协调任务，不能用“可行”隐藏未分配项。
- 报告的 p50、nearest-rank p95、最大值、`target_met` 和 `fallback_used` 必须由有序样本重新计算，不能手写伪造。
- 环境只允许 `windows/linux/macos`、数字格式版本、逻辑 CPU 数和固定单 worker，不定义主机名、本机路径或其他自由环境字段。
- 报告固定使用匿名 `synthetic` 分类和完整安全声明；未知字段与安全声明覆盖均被 Pydantic 拒绝。

## 3. Review 发现与修正

首版 `BenchmarkEnvironment` 使用普通字符串表示平台和版本。虽然模型没有主机名字段，但自由字符串仍可能误带机器名或路径。Review 后将平台收紧为有限枚举，并为 Python/OR-Tools 使用数字版本格式；测试新增私有机器名和本机路径拒绝用例。

基准契约没有公开性能 API，也不读取网络、AI 配置或运行 session。后续 M6-3 使用离线脚本生成报告，避免公开端点成为耗时求解入口。

## 5. 安全、部署与下一入口

- 本单元未读取、复述、写入或调用真实模型密钥；AI 配置继续只允许后端进程环境或部署 secret manager。
- 不接真实机场数据、个人信息或控制系统；`large_aggregate` 只代表匿名合成聚合任务压力档位。
- M6-5 才形成单 origin、单 worker、持久化 SQLite 的 provider-neutral 部署版本；M7 才创建 GitHub 远程、推送并取得公网地址。
