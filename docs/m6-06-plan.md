# M6-6 规模、体验与部署总验收计划

## 1. 目标

M6-6 只验收并收口 M6-0 至 M6-5A 已完成的规模、性能、体验、单 origin 部署和空间态势能力，不新增业务功能。验收必须证明冻结规模输入和报告仍可复现，故障与无模型路径安全可用，真实模型仍然只读，五页工作台和空间态势在多视口可用，部署产物保持单 worker、持久化和秘密隔离边界。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 固定范围

- 继续只使用匿名合成场景和项目原创 2D 空间布局，不接真实机场生产流、个人信息、真实坐标、内部地图或外部控制系统。
- 后端运行会话、revision、仿真时钟、事件、任务、资源、当前方案、候选方案和人工决定继续是唯一权威状态；前端、地图和 AI 不得建立第二状态机。
- AI 只增强事件理解和权威事实表达。无模型、超时、提供方错误或非法输出必须安全回退；真实模型调用也不能应用事件、推进时间、采用候选或控制资源。
- 可选 3D 不属于 M6-6 通过条件。GitHub 远程、推送、托管平台和公网地址属于 M7，本单元不执行。

## 3. 验收矩阵

| 验收面 | 执行方式 | 必须证明 |
| --- | --- | --- |
| 全量回归 | 项目 `.venv` 全量 pytest，前端测试、类型检查和生产构建 | M4/M5/M6 契约、六事件、AI 回退、空间态势和部署契约无回归 |
| 规模性能 | 校验正式报告并运行一组不覆盖报告的三档临时样本 | 小/中型走 CP-SAT，大型显式 `model_size_guard`；全部达标且零硬约束违规 |
| 故障恢复 | SQLite 重启、陈旧 revision、SSE/REST 恢复和标准启停 | 恢复后收敛到同一权威快照，不重放旧命令或生成第二时钟 |
| 无模型 | 本地假提供方与不配置模型的部署路径 | 核心闭环和 `FACT-*`/`SPATIAL-FACT-*` 解释可用，不伪造模型调用 |
| 真实模型 | 使用本机后端已有安全配置进行只读问答冒烟 | `trace.source=language_model`，回答绑定当前 revision，调用前后业务状态不变 |
| 浏览器 | 1440x1000、1024x768、390x844 检查五页、空间态势和资源态势 | 无文档级横向溢出、关键板块不隐藏、控制台正常在线 0 error/0 warning |
| 干净部署 | Docker 契约测试、生产构建、容器 daemon 可用时真实镜像/持久化冒烟 | 单 origin、单 worker、非 root、持久化卷、健康检查和秘密不入镜像 |
| 仓库边界 | 编译、依赖、脚本语法、敏感信息和 Git 差异检查 | 不提交密钥、本机配置、缓存、日志、SQLite 或浏览器临时文件 |

## 4. 环境阻塞口径

- Docker daemon 不可用时，必须记录真实容器复验为环境阻塞；静态契约和既有 M6-5 容器证据不能冒充本轮真实启动结果。
- 外部模型不可用时，记录实际回退原因并继续完成无模型验收，不把规则结果描述为模型调用。
- 浏览器或回环访问被本机策略阻止时，只记录已完成的视口与自动化证据，不能声称未执行的检查通过。
