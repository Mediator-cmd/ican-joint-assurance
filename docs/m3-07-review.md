# M3-7 启停升级审查报告

## 1. 审查范围

本阶段只审查 Windows 一键启动与停止链路，不改变调度算法、API 契约、前端业务状态或安全边界。

- `scripts/start-project.ps1`
- `scripts/stop-project.ps1`
- 根目录 `启动联保智调.cmd` 与 `停止联保智调.cmd` 的调用链
- `.runtime/server-state.json` 的双服务状态记录

## 2. 目标与实现

启动脚本现在把 FastAPI 和 Vite 当作一个服务组管理：

1. 刷新匿名仿真演示数据。
2. 在 `8000-8020` 选择后端端口并启动 Uvicorn。
3. 等待 `/api/v1/health` 返回成功后，再把后端地址写入 `VITE_API_TARGET` 并启动 Vite。
4. 等待前端 URL 可访问后，记录 `ready` 状态并优先用 Microsoft Edge 打开。
5. 失败时按反向顺序回收本次已创建的服务进程，不留下孤立服务。

状态文件使用 `schema_version: 2`，分别记录 `backend` 和 `frontend` 的：

- PID、进程名和 UTC 启动时间；
- 可执行文件路径（可读取时）；
- 端口、URL、健康检查 URL；
- 工作目录和标准输出/错误日志路径。

停止脚本先读取并校验完整状态，再按“前端 → 后端”顺序停止。状态缺失、不可读、项目路径不符、服务名重复、PID 重用或进程身份不符时，不扫描也不结束未知 Python/Node 进程。没有状态文件时重复执行是幂等的。

## 4. 安全审查结论

本阶段未发现高、中、低优先级问题。停止动作是“状态文件授权 + 进程身份三重校验”模型，不通过端口扫描或进程名批量终止，因此不会误停用户的其他 Node/Python 任务。Edge 属于外部浏览器进程，不纳入项目服务组，也不会被停止入口关闭。

## 5. 已知边界

- 当前脚本面向 Windows PowerShell，服务日志保存在本地 `.runtime/`，该目录被 Git 忽略。
- 端口冲突时会在预设范围内自动换端口；状态文件中的实际 URL 是后续访问依据。
- 这仍是本地演示启动器，不是生产进程管理器；M3-8 继续验证完整浏览器流程，M3-9 再做阶段收口。
