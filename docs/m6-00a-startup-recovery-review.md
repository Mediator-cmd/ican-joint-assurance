# M6-0A Windows 一键启动陈旧 PID 恢复审查

## 1. 结论

根目录一键启动入口已能从“旧服务已结束、PID 被其他程序复用”的陈旧状态中自动恢复。脚本会删除无法再代表本项目服务的旧状态，重新启动 FastAPI 与 Vite，并继续优先使用 Microsoft Edge 打开页面。

停止入口仍只结束经过严格身份验证的本项目进程。被其他程序复用的 PID 会被明确跳过，不能仅凭 PID 命中而结束无关进程。

本次仅修复本地启停可靠性，不进入 M6-1，不改变运行时状态、调度结果、AI 辅助边界或数据来源。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 根因证据

- `.runtime/server-state.json` 记录了后端 PID `18472` 和前端 PID `20144`，但两项原服务均已结束。
- PID `20144` 已不存在；PID `18472` 已被一个非本项目、非 Python 的 Windows 进程复用。
- 旧脚本将进程名、启动时间或可执行路径不匹配统一标记为身份冲突，并稳定返回 `Runtime process identity does not match the recorded service`。
- 该保护避免了误杀，但也阻止启动脚本删除已经失效的状态文件，因此用户无法通过标准入口恢复网页。

## 3. 修复与安全边界

- `valid`：记录完整，且实际 PID 的进程名、启动时间和可执行路径均匹配；只有该状态允许复用或停止进程。
- `missing`：记录完整，但 PID 已不存在；无需停止进程。
- `reused`：PID 存在，但进程名、启动时间或可执行路径不匹配；视为旧 PID 已被安全复用，绝不停止当前进程。
- `invalid`：项目路径、服务记录或身份字段本身无法可信解析；继续拒绝自动处理并保留状态以供检查。

当所有记录均为 `missing/reused` 时，启动脚本删除陈旧状态并创建新服务组。当部分记录仍有效或完整服务组不健康时，脚本仅停止 `valid` 的本项目进程，再清理状态并重启。停止脚本对 `reused` 记录输出跳过信息，处理完其他有效记录后删除陈旧状态。

项目根目录、唯一服务名、PID、期望进程名、启动时间和可执行路径校验均未放宽；启动失败回滚、前端后端停止顺序、健康检查、端口选择和日志保留行为也未改变。
