# M5-4 权威方案事实与可追溯解释计划

## 1. 目标

M5-4 只实现只读方案解释服务：对指定场景版本中的已保存方案，或指定运行 revision 中的当前/候选方案，先由后端构造有限权威事实，再输出每条结论都引用事实 ID 的解释。

解释不应用事件、不运行规划器、不修改方案、不推进仿真时间、不增加运行 revision，也不能成为采用候选的隐式命令。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 成功标准

- `POST /api/v1/assistant/plan-explanations` 支持 `scenario_plan` 与 `runtime_plan` 两种上下文。
- 场景方案必须属于请求的场景与版本；运行方案必须是请求 revision 中的当前方案或候选方案。
- 陈旧运行 revision 返回 409，不解释已经变化的候选。
- 摘要、每项取舍和建议下一步都至少引用一个存在的 `FACT-*` 事实 ID。
- 无模型配置时仍能返回完整、可读、可测试的确定性解释。
- 模型超时、提供方错误、非法 JSON、未知事实引用或不完整输出全部回退确定性解释。
- 全部解释固定 `modifies_plan=false`、`requires_human_confirmation=true` 并保留完整安全声明。

## 3. 权威事实来源

| 上下文 | 事实来源 | 禁止来源 |
| --- | --- | --- |
| 场景方案 | 场景仓库中的指定不可变版本和已保存 `Plan` | 前端自报指标、自由文本计划 |
| 运行方案 | `RuntimeSessionService.get_explanation_context()` 一次性返回的当前 revision、`RuntimeSessionSnapshot` 与同 revision 的 `RuntimeProjectionSource` | 旧页面缓存、SQLite 旁路读取 |
| 方案差异 | 同一请求上下文中的可选基线方案与被解释方案 | 其他场景、其他会话或不在当前运行快照中的方案 |
| 硬约束 | `Plan.violations` 与后端已保存指标 | 模型自行判断“可执行” |

事实种类限制为 M5-0 已冻结的七类：目标、计划指标、任务分配、未分配任务、约束、事件和方案变化。事实 ID 由后端按确定性顺序生成，不由模型提供。

## 4. 解释策略

### 4.1 确定性默认解释

规则解释直接消费权威事实，按请求 focus 组织摘要、取舍和下一步：

- `summary`：方案状态、任务覆盖、P1 保障和硬约束结论。
- `tradeoffs`：目标配置、等待、资源利用、未分配原因和可选基线差异。
- `task_changes`：逐任务新增、移除、资源变化或时间变化。
- `manual_handling`：未分配任务、硬约束和人工复核动作。

规则解释是完整产品能力，不是错误占位。GitHub 克隆、本地演示和未配置密钥的公网实例均可直接使用。

### 4.2 可选模型增强

配置完整 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 时，`auto` 模式可以把有限事实、focus 和可选匿名问题发送给 OpenAI-compatible 提供方。不得发送场景 JSON、运行 session/revision、SQLite、审计、本机路径或其他会话数据。

模型只返回结构化 claim 和事实 ID 引用。后端重新通过 Pydantic 校验所有引用；任何失败都回退规则解释，并只公开有限 `fallback_reason`。`deterministic_only` 保持零外部调用。

## 5. 错误语义

| HTTP | code | 条件 |
| --- | --- | --- |
| 404 | `assistant_context_not_found` | 场景、版本、会话或方案不存在 |
| 409 | `assistant_revision_conflict` | 运行 revision 已变化 |
| 409 | `assistant_plan_context_mismatch` | 方案不属于指定场景/版本，或不在当前运行方案集合 |
| 422 | `validation_error` | 上下文、focus、问题或模型契约非法 |

模型不可用不返回 5xx；它只改变 `trace`，不改变权威事实和业务状态。

## 6. GitHub 与公网部署约束

- 无密钥启动、健康检查、M4 实时闭环和确定性解释必须全部可用。
- 密钥只由部署平台环境变量注入，不进入 Git、前端 bundle、构建参数、日志、审计或 API 响应。
- 不使用 DeepSeek 专用 SDK；保持 OpenAI-compatible HTTP 适配器，便于不同公网平台替换提供方。
- 后端不依赖本机绝对路径处理解释请求；响应不暴露内部路径或提供方 URL。
- M6 负责形成部署版本，M7 负责 GitHub 源码、运行说明和稳定公网地址；M5-4 不提前绑定具体托管商。

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 模型引用不存在的事实或编造结论 | 严格结构化输出、事实 ID 白名单、失败回退规则解释 |
| 解释旧候选导致误判 | 每次请求重新读取运行快照并核对 revision 与方案 ID |
| 证据过多导致响应或模型请求膨胀 | 指标全量、任务/事件有限排序并保持 100 条契约上限 |
| AI 配置成为部署前置条件 | 规则解释作为默认完整能力，模型只做可选增强 |
| 密钥泄露到 GitHub 或浏览器 | 仅服务端环境变量，SecretStr、最小错误和仓库敏感模式扫描 |
