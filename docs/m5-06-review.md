## 2. 跨 API 总验收

新增 `tests/test_m5_acceptance.py`，只通过公开 REST API 和本地假提供方验证同一运行会话的三轮完整闭环：

1. `deterministic_only`：规则生成事件草稿，提供方调用数保持 0；双重确认前 revision、事件与方案完全不变，确认后只产生待确认候选。
2. 模型成功：假模型从非固定规则表达中抽取事件，结果仍经原文 quote、权威航班、权威时间和 Pydantic 契约复核；事实解释只引用响应中存在的 `FACT-*`。
3. 注入与非法输出：文本包含“立即执行、自动采用”等越权指令，假模型返回未知实体，解释模型返回不存在的事实 ID；两者均回退确定性结果，仍要求人工提交和人工决定。

三轮分别执行“保留、采用、保留”，断言场景版本和 revision 严格递增、候选 ID 不重复、当前方案只在第二轮人工采用后改变。解释请求前后运行快照完全相同，证明解释只读。

三类提供方故障另以参数化总验收覆盖：超时、请求错误和非法结构在事件草稿与方案解释两条 API 上均返回安全规则回退；响应不回显原始输入、异常类型、内部配置或可执行越权内容。

## 6. 真实 DeepSeek 与密钥边界

这不作为 M5 回归阻塞：模型成功、失败和非法输出路径使用本地假提供方覆盖，OpenAI-compatible HTTP 适配器已有请求/响应级单元测试；无模型路径完成了真实浏览器三轮。部署或单独真实冒烟时，必须由用户在本机可见终端或托管平台 secret manager 中设置三个后端进程环境变量后重启服务，再以响应 `trace.source=language_model` 作为实际调用证据。密钥不得进入 GitHub、前端 bundle 或 API 响应。
