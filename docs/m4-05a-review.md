# M4-5A 有限事件序列与方案内容可读性修正审查记录

## 1. 审查结论

M4-5A 已完成。原教学场景在第二条事件后只剩时间和既定任务边界推进的问题已修正：当前场景包含 6 条固定、一次性扰动，第三至第六条事件均会生成新的场景版本和唯一候选，最终在 09:30 正常完成且不回绕。

当前与候选方案不再只显示英文 ID。运行快照直接公开后端持久计划事实，页面逐项说明方案用途、指标、任务、航班、资源、服务时段、路线、人工协调原因和候选差异。候选没有改变安排时，页面明确说明“复核未改变任务安排”，不会为了制造新鲜感而篡改已冻结事实。

本单元是 M4-5 后、M4-6 前的独立修正，不计入 M4-6，也不表示整个 M4 已完成。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 实现范围

### 2.1 六事件非循环场景

- 场景扩展为 3 个虚构航班、10 项匿名任务和 5 项资源，窗口为 08:00 至 09:30。
- 事件固定发生在 08:00、08:04、08:16、08:28、08:40、08:52，包含三次延误和三次登机口调整。
- `RuntimeProjectionSource.event_catalog` 继续是唯一事件目录；事件由后端时钟触发并原子应用一次，不使用随机数、不无限生成、不循环。
- 后段释放任务和资源为后续规划提供事实；若事件发生时相关任务已锁定，优化器可以返回安排不变的新候选并给出真实说明。

### 2.2 权威快照与兼容恢复

- `RuntimeSessionSnapshot` 增加 `active_plan_detail` 和 `candidate_plan_detail`，并校验明细 ID 与顶层方案 ID 一致。
- 明细只来自 SQLite 持久化 `RuntimeProjectionSource.plan/candidate_plan`；旧会话缺失投影依据时返回空，不补造任务或指标。
- `EventRuntimeProjection` 公开事件类型、航班 ID、中文事实和备注，前端不再依赖静态演示 JSON 拼接事件含义。
- 会话复用同时核对场景版本、初始方案 ID、完整任务 ID 和事件 ID 集合；旧 2 事件会话不会冒充新场景会话。

### 2.3 方案任务书与真实差异

- 当前与候选方案均展示已安排/总任务、平均等待、资源利用率、关键任务完成率和硬约束违规数。
- 每项安排显示中文任务类型、虚构航班、资源类型与 ID、服务时段和中文区域路线；未安排任务显示结构化中文原因。
- 候选说明触发事件、冻结事实数量和只调整未来任务的规则，并区分安排状态、资源、时间、路线、等待与人工协调变化。
- 事件进入 `resolved` 后，“关联候选”显示“已完成人工确认”，不再与完成状态矛盾。

## 3. 状态所有权与禁止事项

- 后端权威时钟、运行状态机、事件目录、任务投影、当前计划和候选计划保持唯一所有权。
- CP-SAT 只在事件边界或人工请求时运行，候选先经过独立硬约束复核，再冻结等待人工确认。
- 前端只显示后端事实，不增加第二时钟、事件生成器、任务状态机、随机变化或规划器。
- 不接真实机场生产数据、旅客个人信息、生产消息总线或控制系统。
- 不让 AI 直接生成或切换计划；后续 AI 只能解析、追问和解释，不能绕过 CP-SAT、硬约束复核和人工确认。

## 5. 已知边界与 M4-6 入口

- 六事件是有限、可复现的教学样本，不是无限实时事件源，也不代表真实机场生产流量。
- 事件事实不同不保证任务安排必然改变。后段任务均已冻结时，返回“0 项调整”的新候选是正确结果；制造随机资源或时间变化会破坏审计和已发生事实。
- 当前解释由确定性结构化事实生成；AI 事件理解、缺失字段追问和更自然的解释属于 M5 或后续范围。
- M4-6 仍需完成性能、长时间、故障、多页面一致性和桌面/移动三轮连续演示。完成这些退出条件前，不得宣称整个 M4 完成。
