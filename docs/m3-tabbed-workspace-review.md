# M3 界面检查点：标签式联合保障工作台

## 1. 调整目标

本检查点先于 M3-5 实施，解决原演示页依赖左侧锚点和整页纵向滚动的问题。调整后的目标不是增加装饰性页面，而是让用户在固定工作台中按任务切换视角，并能从结论继续追溯到任务、事件、资源和计算依据。

本检查点不改变 M2/M3 调度结果，不在前端重新计算指标，不接入自然语言 AI，也不替代后续 API 联调。

## 2. 五页信息架构

| 页面 | 首要问题 | 核心功能 | 跨页入口 |
| --- | --- | --- | --- |
| 调度总览 | 当前方案是否值得采用 | 推荐结论、四项核心指标、三方案对照、运行关注事项 | 前往任务、事件、最高负载资源和方案依据 |
| 任务计划 | 每项任务由谁在何时执行 | 全部/紧急/待协调筛选、任务选择、路径与时限、关联航班和执行资源 | 从任务详情进入对应资源 |
| 事件影响 | 哪项扰动改变了什么 | 事件选择、影响摘要、业务解释、字段前后值 | 与全局方案视图联动 |
| 资源态势 | 哪项资源繁忙、何时何地可用 | 资源选择、负载评估、当前位置、待命区域、可用时段、任务序列、区域覆盖 | 从执行序列返回任务详情 |
| 方案依据 | 结果为什么可信、适用边界是什么 | 独立硬约束复核、五步计算链路、版本与算法、指标口径 | 与全局方案视图联动 |

左侧导航全部使用按钮状态切换，不再跳转页面锚点。任一时刻 DOM 中只有一个 `.workspace-page`，避免用户误以为仍需继续向下寻找内容。

## 3. 固定视口与滚动规则

- 桌面端应用固定为 `100dvh`，`html/body/#root`、主工作区和页面容器均不产生整页滚动。
- 桌面端只有任务表、事件清单、资源清单等内容容器可在数据增长时内部滚动。
- 390×844 移动端将左侧导航转换为顶部横向标签栏；标签栏横向滚动，当前页面内部纵向滚动，浏览器文档本身保持不滚动。
- 安全声明固定在底部，桌面端单行显示，移动端允许换行但不隐藏正文。

## 4. 用语调整

当前界面在普通用户可理解的前提下，统一采用更正式的业务表达：

- `原始计划`：扰动发生前的方案比较基准。
- `规则重排`：事件生效后仍按任务到达顺序形成的对照方案。
- `优化方案`：满足硬约束并优先保障紧急任务的推荐结果。
- `待协调任务`：当前方案未分配执行资源，需要人工处理的任务。
- `独立约束复核`：与方案生成分离的资源、容量、时间窗和路径检查。

算法名称和版本没有删除，集中放在“方案依据”页供答辩和技术复核使用。

## 7. 安全与产品边界

页面继续显示：**仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。**

所有方案结果、变化记录和指标继续来自确定性调度与结构化校验；前端只负责选择、组织和解释后端数据，不生成或修改调度结论。
