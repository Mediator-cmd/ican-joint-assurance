# M6-3 离线基准与 FIFO/有界规划对比审查

## 1. 结论

M6-3 已完成。项目新增离线 `run_scale_benchmark_suite()` 和命令行入口，在 M6-1 冻结的三个匿名合成场景上执行固定 1 次预热及每档 5 组 FIFO/有界规划配对样本，并生成严格校验的 [m6-benchmark-report.json](m6-benchmark-report.json)。

正式报告显示，小型、中型和大型聚合档位的有界入口最大耗时分别为 1.022711、3.113737 和 2.776355 秒，满足 2/5/15 秒测试口径。小型和中型的 5 个样本全部实际走 CP-SAT 且不回退；大型聚合的 5 个样本全部在建模前公开触发 `model_size_guard`，返回确定性安全回退。全部 FIFO 与有界样本均完整覆盖任务，硬约束违规为 0。

这些结果只适用于本报告记录的 Windows、Python 3.13.9、OR-Tools 9.15.6755、24 个逻辑 CPU、单求解 worker 和冻结合成场景，不外推为真实机场生产吞吐、其他主机或公网部署承诺。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 可复跑口径

正式命令为：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_scale_benchmark.py --warmup-runs 1 --measured-runs 5 --output .\docs\m6-benchmark-report.json
```

运行器在计时前生成并严格验证规范 `ScaleScenarioArtifact`。每档先依次预热 FIFO 和有界入口，再按连续 `run_index=1..5` 成对计时。每次计时从已验证场景交给规划入口开始，到任务书完成独立 `validate_plan()` 为止；场景生成、JSON 写入、网络、浏览器、AI 和依赖冷启动不计入样本。

小型、中型和大型的固定求解器预算分别为 1、3、9 秒，为完整 2/5/15 秒入口保留模型构建、任务书构造和独立复核余量。大型在建模前触发 guard，因此其 9 秒求解预算没有实际进入 CP-SAT。

小/中型任务书算法随本次完整入口预算和真实行程左移修正升级为 `bounded_scale_cp_sat_v2`；报告每个样本同时保存执行路径与算法名，不能用 `cp_sat` 标签掩盖实际实现版本。大型继续使用 `deterministic_scale_fallback_v1`，FIFO 对照继续使用 `fifo_baseline_v1`。

报告使用 `perf_counter()`，将单次耗时保留到 6 位小数；p50 为中位数，p95 为 nearest-rank 95%，最大值为有序样本最大值。`target_met` 只由有界路径最大值与档位目标比较得出。

## 3. 正式性能样本

| 档位 | 目标 | FIFO p50 / p95 / 最大值 | 有界 p50 / p95 / 最大值 | 实际路径 | 回退 | 结论 |
| --- | ---: | --- | --- | --- | --- | --- |
| `small` | 2 秒 | 0.004037 / 0.004135 / 0.004135 秒 | 1.022186 / 1.022711 / 1.022711 秒 | `cp_sat` | 否 | 达标 |
| `medium` | 5 秒 | 0.071471 / 0.073085 / 0.073085 秒 | 3.111318 / 3.113737 / 3.113737 秒 | `cp_sat` | 否 | 达标 |
| `large_aggregate` | 15 秒 | 2.566123 / 2.577711 / 2.577711 秒 | 2.747334 / 2.776355 / 2.776355 秒 | `deterministic_fallback` | `model_size_guard` | 达标 |

所有 30 个正式计时样本（3 档 × 2 条路径 × 5 轮）均完成独立硬约束复核。报告保留每个样本的实际路径、有限回退原因、方案状态、任务覆盖、平均/最大等待、完成率、关键任务完成率和资源利用率，汇总值不能脱离样本手写覆盖。

## 4. FIFO 与有界方案质量对比

严格报告固定以第一组同档配对样本生成 `comparison`，其余每轮原始指标仍逐项保留。三档 FIFO 和有界结果均完整分配 100/500/2000 项任务，任务完成率和关键任务完成率均为 100%，硬约束违规均为 0。

| 档位 | FIFO / 有界平均等待 | FIFO / 有界最大等待 | FIFO / 有界利用率 |
| --- | --- | --- | --- |
| `small` | 0.00 / 0.57 分钟 | 0 / 10 分钟 | 7.83% / 7.94% |
| `medium` | 0.03 / 1.11 分钟 | 6 / 21 分钟 | 20.07% / 20.97% |
| `large_aggregate` | 0.00 / 0.00 分钟 | 0 / 0 分钟 | 22.53% / 22.53% |

冻结规模场景资源充足、任务释放均匀，因此确定性 FIFO 已接近零等待。不能从该场景声称 CP-SAT 在等待或速度上优于 FIFO。小/中型有界模型优先保证关键任务、完整覆盖和受限模型规模，并为无两两排序建模保留保守行程缓冲；任务书重建已按求解器资源/顺序和真实最短路左移到最早可行时间，但在当前轻负载数据上等待仍高于 FIFO。该差异是正式证据的一部分，不通过替换冻结输入、隐藏样本或把 FIFO 方案冒充 CP-SAT 来消除。

大型有界入口因规模保护明确复用安全确定性核心，所以其任务指标与 FIFO 相同；额外耗时来自模型规模估算、候选检查、结果绑定和最终复核。

## 5. 报告契约与安全边界

`ScaleBenchmarkReport` 现在同时绑定：

- 规范档位、场景 ID/version 和 M6-1 冻结 SHA-256；
- 固定求解预算、有限环境字段、预热次数和成对样本数；
- FIFO 样本必须使用 `fifo_baseline`，有界样本不得冒充 FIFO；
- 小/中型只能记录 CP-SAT，大型回退必须携带有限原因；
- 连续轮次、任务覆盖、完成率、零硬约束违规和第一组配对质量对比；
- 从样本重新推导的 FIFO/有界 p50、nearest-rank p95、最大值、目标状态和回退状态。

`ScaleBenchmarkSuite` 只接受按 `small`、`medium`、`large_aggregate` 顺序排列的三份报告，并要求时间、环境、预热/样本数和总达标状态一致。报告拒绝主机名、本机路径、密钥、用户原文、真实机场字段及未知字段；运行器不访问网络、AI、SQLite、实时 session/revision 或公开 API。
