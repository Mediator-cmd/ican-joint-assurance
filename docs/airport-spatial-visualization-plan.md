# 机场空间态势与方案路径可视化实施计划

## 1. 决策结论

该能力已经完成 M6-5A 的 2D 实施与 M6-6 总验收，并与联保智调现有实时仿真、滚动重规划和人工确认链路保持同一权威状态。当前版本采用原创、匿名、可公开部署的 2D SVG 机场航站楼示意图；在不改变五页工作台结构的前提下，把“空间态势”嵌入调度总览并提供放大模式、方案路径、资源进度、事件定位和 revision-bound 空间 AI 问答。下一唯一入口为 M7 比赛材料与最终发布；可选 3D 不作为首次 GitHub 公网发布的前置条件。

真实或近似北京大兴机场的底图只有在来源、授权、用途和可公开发布范围明确后才能导入。未经授权的公开图片、商业地图截图、内部运行图、安防/限制区细节和真实生产坐标不得进入仓库。默认底图必须标注“匿名机场仿真空间示意图”，不能让视觉真实感改变产品的教学仿真定位。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 当前源码可复用能力

| 已有事实 | 当前字段 | 空间展示用途 |
| --- | --- | --- |
| 区域与通行关系 | `Zone.zone_id/name/travel_minutes` | 校验空间节点及可达关系；不能直接推断几何位置 |
| 任务起终点 | `ServiceTask.origin_zone_id/destination_zone_id` | 绘制任务保障路径和问题影响范围 |
| 方案任务书 | `Assignment.resource_id/resource_type/travel/service time/origin/destination` | 展示当前方案、候选方案、执行时段和资源路线 |
| 资源实时位置 | `RuntimePosition.from_zone_id/to_zone_id/progress_pct` | 按后端权威进度放置移动资源，不使用前端随机运动 |
| 事件与航班 | `EventRuntimeProjection.flight_id/status`、`FlightRuntimeProjection.gate_id` | 将延误定位到当前登机口，将登机口变更连接到前后位置 |
| 实时更新 | `RuntimeSessionSnapshot`、SSE、2 秒 REST 恢复 | 与现有仿真时钟、revision 和断线恢复保持一致 |
| 当前/候选方案 | `active_plan_detail/candidate_plan_detail` | 当前路线用实线，候选变化用虚线，采用前不替换当前路线 |

当前缺口是确定性的空间几何：区域坐标、区域轮廓、路径折线、楼层、图层顺序、底图来源和许可证。上述信息必须新增为空间布局契约，不能从通行时间、名称或 AI 文本中猜测。

## 3. 产品体验

### 3.1 调度总览中的空间态势

- 总览新增“机场空间态势”主板块，默认展示整个航站楼，可进入放大模式，但不增加第六套业务状态。
- 机场示意图使用中央大厅与放射式指廊的原创矢量结构，保留大兴机场大型枢纽的直观感受，但不复刻或声称等同真实平面图。
- 右上角图层开关只控制显示：事件、任务、资源、当前方案、候选方案和区域标签。
- 地图与现有任务、资源、事件选择共享同一选中 ID。点击地图标记会打开现有详情；从现有列表查看对象时地图同步聚焦。

### 3.2 实时问题定位

- 航班延误：在航班当前登机口显示带状态颜色的事件标记，展开后显示事件时间、航班、延误分钟数和处理状态。
- 登机口变更：旧登机口与新登机口同时标记，中间使用方向虚线；事件完成后保留审计痕迹但降低视觉强度。
- 受影响任务：起点、终点和关联资源高亮；冻结任务与未来可调整任务使用不同边框，不能把已发生事实画成待执行建议。
- 资源不可用或减少：在资源最后权威位置标记异常，受影响任务路径同时显示待协调状态。

### 3.3 方案实施过程

- 当前执行方案：深绿或蓝色实线；正在移动/服务的资源按后端 `progress_pct` 放置在线段上。
- 待确认候选：琥珀色虚线，显示相对当前方案新增、改道、换资源或转人工协调的任务；确认前不得覆盖当前实线。
- 采用候选后：只在收到新的权威快照和 revision 后切换样式；拒绝候选后虚线消失，当前方案保持。
- 动画只用于两个权威快照之间的视觉插值，并以快照的仿真时间和进度为终点；页面失焦、断线或暂停时停止，不循环播放、不随机生成轨迹。

### 3.4 AI 空间态势助手

AI 必须成为空间态势的实际解释入口，不能放置一个脱离地图和运行进程的通用聊天框：

- 用户可直接询问“当前问题发生在哪里”“该区域有哪些受影响任务”“哪辆资源正在赶往现场”“候选方案为什么改走这条路线”“目前处理到哪一步”“下一个权威边界是什么”。
- 从地图点击事件、区域、资源或路线后，问题自动绑定当前 `session_id + revision + simulation_time + selected entity IDs`；AI 只读取后端为该上下文生成的有限权威事实。
- 回答必须引用 `SPATIAL-FACT-*`，并区分当前执行事实、待确认候选、已完成审计和未知信息。没有证据时明确回答“当前权威快照未提供”，不能补造机场结构或处理进度。
- 回答可返回经过后端白名单校验的 `focus_entity_ids`。前端只据此聚焦/高亮地图对象，不执行任务、不采用方案、不改变 revision。
- 预置问题覆盖定位、影响、资源、路线、进度和下一步；同时允许匿名自然语言追问。规则模式必须能回答基础问题，真实 DeepSeek 成功时负责更自然的多事实解释。
- 每次快照 revision、方案、选择对象或问题变化后旧回答标记过期，不能把旧事件答案继续显示为当前机场状态。

## 4. 空间数据契约

新增与场景版本绑定的只读 `SpatialLayout`，建议字段如下：

```text
layout_id / scenario_id / scenario_version
projection = normalized_cartesian
canvas = { width, height }
asset = { kind, source_class, license, sha256 }
zones[] = { zone_id, label, floor, anchor, shape }
paths[] = { path_id, from_zone_id, to_zone_id, points, direction, accessible }
safety_notice
```

约束：

1. 坐标使用 0–1 规范化本地坐标，不包含真实经纬度。
2. 所有区域必须引用场景已有 `zone_id`；路径端点必须存在，折线点有限且坐标在画布范围内。
3. 路径几何与 `travel_minutes` 是不同事实：前者只用于展示，后者继续由调度和硬约束拥有。
4. 底图资产必须绑定 SHA-256、来源类型和许可证；未知来源、远程热链或包含脚本的 SVG 被拒绝。
5. M6 规模场景可没有空间布局；缺失时页面显示明确空态，不能自动随机摆放节点。

后端再从 `SpatialLayout + RuntimeSessionSnapshot + active/candidate Plan` 严格派生只读 `RuntimeSpatialOverlay`：

```text
session_id / revision / simulation_time / layout_id
event_markers[]
resource_markers[] = { resource_id, path_id, progress_pct, status }
task_routes[] = { task_id, route_kind, path_ids, status, plan_id }
focus_hints[]
```

该投影随现有 REST/SSE 权威快照更新。它不新增时钟、规划器或候选所有权；前端只把 path 和 progress 转成 SVG 像素，不计算业务状态。

新增只读空间问答契约 `POST /api/v1/assistant/spatial-questions`：

```text
request:
  context = { session_id, expected_revision, selected_entity_ids }
  question / assistance_mode

response:
  context = { session_id, revision, simulation_time, layout_id, selected_entity_ids }
  trace = { source, provider_attempted, model_label, fallback_reason }
  answer / situation_summary / process_stage / recommended_next_step
  evidence[] = { fact_id = SPATIAL-FACT-*, entity_ids, claim }
  focus_entity_ids[]
  requires_human_confirmation = true
  modifies_plan = false
  safety_notice
```

服务端事实构建器从事件、航班登机口、资源位置、任务状态、当前/候选计划和 overlay 生成 `SPATIAL-FACT-*`。模型输出中的事实引用和聚焦 ID 必须全部存在于该集合；未知实体、无效路径、越权执行语句、陈旧 revision 或非法结构触发确定性规则回退。API key 仍只保存在后端进程或部署 Secret Manager，空间页面不接触提供方地址或密钥。

## 5. 技术路线

### 5.1 第一版：2D SVG

- 原因：SVG 可响应式缩放、支持路径和虚线、无地图 API key、资源体积小、容易在 GitHub 和单 origin 公网部署中缓存。
- 前端使用 React 原生 SVG，不引入地图供应商 SDK，不远程加载瓦片。
- 标记与路径数量采用与 M6-4 相同的有界视窗策略；默认只绘制当前视口和用户选择相关对象，聚合场景不把 2000 项同时写入 DOM。
- 颜色之外同时使用线型、图标和文字，满足色觉与移动端可读性要求。

### 5.2 第二版：2.5D/3D 渐进增强

- 在 2D 契约和交互验收后，复用同一布局与 overlay，选择 CSS/SVG 透视或本地 glTF/WebGL。
- 3D 只是可切换展示层；WebGL 不可用、移动设备性能不足或开启减少动态效果时自动回到 2D。
- 3D 模型同样必须本地托管、绑定许可证和摘要，不接入真实生产坐标或外部控制系统。

## 6. 分阶段实施顺序

### M6-5：当前进程不变

先完成 provider-neutral 单 origin 部署版本，包括单 worker、同源 API、SQLite 持久化卷、健康检查、非 root、请求限制、错误脱敏和平台 Secret Manager。空间计划不能阻断或扩展 M6-5 的秘密权限。

### M6-5A-0：空间契约与原创布局

- 新增严格 `SpatialLayout`/`RuntimeSpatialOverlay` 模型、JSON Schema 和非法引用/坐标/许可证测试。
- 创建原创匿名枢纽机场 SVG 与三类示例区域；资产本地托管并记录 SHA-256。
- 冻结图层、颜色、线型、移动降级和完整安全标识。

### M6-5A-1：权威后端投影

- 将延误定位到航班当前登机口，将登机口变更映射到前后区域。
- 将资源 `from/to/progress_pct` 和当前/候选任务路线映射到有限 path ID。
- 与现有 session/revision、SSE 和 REST 恢复绑定，验证暂停、断线和候选采用/拒绝。
- 构建有限 `SPATIAL-FACT-*` 证据集和规则问答，覆盖问题位置、影响任务、活动资源、处理阶段、当前/候选路线与下一权威边界。

### M6-5A-2：2D 总览与联动

- 在调度总览加入空间态势和放大模式，共享任务/资源/事件选择。
- 实现图层开关、事件定位、实线当前方案、虚线候选方案和处理过程标记。
- 在空间态势内接入 AI 问答：地图选择形成问题上下文，回答引用证据并可聚焦经过后端校验的相关对象；旧 revision 回答立即过期。
- 完成 1440×900、390×844、键盘、色觉、减少动态效果和无 WebGL 浏览器测试。

### M6-5A-3：方案演进与演示场景

- 使用现有六条一次性事件验证不同事件产生不同空间变化，不创建循环或随机事件。
- 验证候选出现前后、采用、拒绝、REST 恢复和重启恢复的视觉审计一致性。
- 对每类连续事件验证规则/真实模型空间问答，确保回答随 revision 和处理进程变化，不重复旧模板、不出现无证据位置或方案描述。
- 保留现有中文方案详情、AI 事实解释、分页、移动布局和安全声明。

### M6-5A-4：可选 3D

只有 2D 退出条件全部通过且部署性能预算允许时才进入。3D 不作为 M6-6 或首次 GitHub 公网发布的必要条件。

## 7. 验收条件

- 同一 revision 下地图标记、列表详情、当前方案和候选方案完全一致。
- AI 能基于同一 revision 回答位置、影响、资源、路线、处理阶段和下一步，所有结论带合法 `SPATIAL-FACT-*`，并准确区分当前事实与待确认候选。
- AI 返回的地图聚焦对象全部经过后端实体白名单校验；模型未配置、超时、提供方错误或非法输出时规则回答仍可用。
- 暂停时资源不移动；SSE 断开时只按 REST 权威快照恢复；不得在浏览器继续自推进。
- 六条既有事件能产生可区分的位置、路径或状态变化；完成后不循环重播。
- 候选始终为虚线且采用前不替换当前实线；采用/拒绝必须经过人工命令和新 revision。
- 2D 首屏不依赖外网地图服务、API key 或真实机场数据；干净部署无 AI 时仍可运行。
- 390×844 无文档级和地图卡片内部横向滚动；键盘可以聚焦标记并读取中文说明。
- 大集合以聚合、筛选和选中对象为主，默认 SVG DOM 有明确上限。
- 所有图像、SVG、GeoJSON 或 glTF 均有来源、许可证、摘要和安全分类。

## 8. 风险与禁止事项

- 禁止把“视觉上像真实机场”表述为已接入机场生产数据。
- 禁止未经授权复制北京大兴机场平面图、商业地图截图或内部运行图。
- 禁止用 AI 根据区域名称猜坐标、路径、楼层或受限区域。
- 禁止提供脱离当前 session/revision 的通用机场聊天框，或让 AI 在没有 `SPATIAL-FACT-*` 时声称知道现场位置、进度和路线。
- 禁止建立地图专用仿真时钟、随机资源运动、循环事件或前端规划器。
- 禁止让地图点击直接执行放行、登机、改签、车辆控制或自动采用候选。
- 禁止为了 3D 引入必须访问外网、暴露密钥或显著破坏移动端/公网冷启动的依赖。

## 9. 工程量与最终建议

2D 契约、后端投影、`SPATIAL-FACT-*`/AI 问答、SVG 总览、联动和验收预计 4–7 个工程日；可选 3D 另需 3–5 个工程日，且取决于模型资产授权与移动端性能。最稳妥的比赛版本是先交付高完成度 2D：它已经能直观表现问题位置、资源移动、任务路线、候选变化和解决过程，并让 AI 根据当前空间事实回答位置、影响和进度，同时保持现有实时闭环、部署与安全优点。3D 可作为后续增强，不应牺牲可靠性或推迟首次稳定公网版本。
