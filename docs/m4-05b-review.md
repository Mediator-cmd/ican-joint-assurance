# M4-5B 方案依据完整展示修正审查记录

## 1. 审查结论

M4-5B 已完成。方案依据页不再使用固定三行高度或板块内部滚动，当前执行方案、待确认候选、完整方案任务书、受影响任务、权威证据和运行链路按内容自然展开。页面只保留工作页级纵向滚动，桌面和移动端均可连续查看全部事实，不再出现顶部板块被压缩、任务书大片空白或内容被裁切的问题。

方案状态也不再以 `PLAN-...` 审计编号作为主要内容。当前和候选卡首先显示中文算法名称、已安排任务、关键任务完成率和硬约束结果，编号降为次级审计信息；下方任务书继续逐项显示任务、虚构航班、资源、服务时段、路线和人工协调原因。这些内容直接来自后端权威计划，不依赖未来 AI 接入。

本单元是 M4-5A 后、M4-6 前的展示修正，不计入 M4-6，也不表示整个 M4 已完成。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 2. 根因与处理

### 2.1 方案内容仅显示编号

- 正式后端仍是 M4-5A 提交前启动的旧进程，其 OpenAPI 和运行快照没有 `active_plan_detail`、`candidate_plan_detail`，页面只能如实显示方案 ID。
- 使用项目一键脚本安全重启正式服务后，后端重新加载当前源码和六事件教学数据；OpenAPI 已包含两项方案明细，页面可读取 10 项任务的完整计划事实。
- 前端没有根据方案 ID 补造内容。若权威快照只含 ID，页面明确显示“方案明细尚未同步”，提示刷新权威快照或重启项目服务。

### 2.2 板块狭小、滚动和空白

- 原 `.runtime-evidence-layout` 使用固定三行网格，并给方案任务列表、依据列表和运行链路分别设置高度或滚动，内容长度不一致时会同时造成压缩、裁切和空白。
- 方案依据改为自然高度的纵向布局，所有子板块按实际内容完整展开；任务列表、证据列表和运行链路取消内部滚动。
- 权威证据在宽屏为三列，中等宽度为两列，手机为单列；移动端运行链路改为单列，不产生横向滚动。

## 3. 方案说明与状态所有权

- `CP-SAT 约束优化`、`滚动约束优化`等中文名称只映射后端算法标识，不改变算法结果。
- 已安排任务数、关键任务完成率和硬约束数直接读取后端 `Plan.metrics` 与 `Plan.violations`。
- 逐项任务书与候选差异继续读取 `active_plan_detail`、`candidate_plan_detail`，不在前端运行规划器或推导计划。
- 后端权威时钟、事件目录、任务投影、当前计划、候选计划、CP-SAT、硬约束复核和人工确认仍是唯一业务状态来源。
- AI 后续可以增强事件理解和解释表达，但不得直接排班、虚构变化、绕过硬约束检查或替代人工确认。
