# M4-5A 有限事件序列与方案内容可读性修正计划

## 1. 修正定位

M4-5A 是 M4-5 完成后的独立修正单元，先于 M4-6 执行。它解决两项已由源码和真实页面确认的问题：

1. 当前合成场景只有 08:00、08:04 两条事件，第二条事件处理完成后只有时钟和既定任务边界继续推进，不会再出现新扰动或事件候选。
2. 运行快照只公开当前方案与候选方案 ID，完整计划虽然已持久化在 SQLite 投影依据中，但前端无法说明每个方案具体安排了哪些任务、资源、时间和路线。

本单元不计入 M4-6，不宣称 M4 全阶段完成。

## 2. 状态所有权

- 后端权威仿真时钟继续是唯一时间来源，前端不得自行计时或制造事件。
- `RuntimeProjectionSource.event_catalog` 继续持有有限、可复现、一次性事件目录；事件只按 `occurred_at` 原子应用一次。
- `RuntimeProjectionSource.plan` 与 `candidate_plan` 继续分别持有当前执行方案和待确认候选的完整事实。
- CP-SAT 继续只在事件边界或人工请求时运行；已完成、移动中、等待中和服务中的任务继续冻结保护。
- 候选方案通过独立硬约束复核后仍必须由人工明确采用或保留，不能静默替换当前方案。
- 前端只展示后端计划事实和两方案差异，不在浏览器中排班、推导任务状态或伪造指标。

## 3. 实施范围

### 3.1 有限非循环事件序列

- 保留现有 08:00 延误与 08:04 登机口变更，维持原有单轮椅冲突和 FIFO/CP-SAT 对照价值。
- 在运行窗口中后段增加四条不同的延误或登机口变更事件，并增加后段释放的匿名保障任务，使后续事件仍会作用于尚未开始的工作。
- 所有事件 ID、发生时间和载荷固定，运行可复现；不使用随机数、不无限生成、不在窗口结束后回到起点。
- 每条事件继续产生新的场景版本和唯一滚动候选 ID；事件处理完成后必须人工决定并显式继续运行。

### 3.2 运行快照方案与事件明细

- 快照增加当前执行方案与待确认候选的完整计划明细，字段 ID 必须与顶层 `active_plan_id`、`candidate_plan_id` 一致。
- 兼容无法恢复投影依据的旧 SQLite 会话：方案明细允许为空，前端明确显示明细不可用，不补造事实。
- 事件投影直接公开事件类型、航班 ID、中文事实说明和备注，避免未来事件只能退化为英文 ID。
- 运行会话找回除版本和初始方案 ID 外，还需核对任务 ID 与事件 ID 集合；结构不同的旧会话不得冒充当前场景会话。

### 3.3 前端方案内容

- 当前方案和候选方案均展示已安排/总任务、平均等待、资源利用率、硬约束违规数。
- 每项已安排任务展示任务类型、航班、执行资源、服务时段和保障路线。
- 未分配任务展示中文原因及后端详情。
- 候选存在时展示新增安排、转人工协调、资源变化、时间变化、路线变化和保持不变项数量。
- 说明候选针对哪些事件、冻结了哪些执行事实，以及它只调整未来任务；AI 后续只增强自然语言解析和解释。

## 4. 禁止事项

- 不接真实机场生产数据、旅客个人信息或运行控制系统。
- 不实现循环播放、无限事件流、前端随机数或随机事件生成器。
- 不让 AI 直接生成或篡改计划，不绕过 CP-SAT、硬约束复核和人工确认。
- 不创建第二时钟、前端事件引擎、前端任务状态机或前端规划器。
- 不提前实施 M4-6 的性能、故障、长时和三轮总验收，也不宣称 M4-6 已完成。

## 5. 验收矩阵

| 验收项 | 通过条件 |
| --- | --- |
| 场景完整性 | JSON UTF-8 可校验；事件、任务、航班、资源和区域引用全部有效 |
| 非循环序列 | 事件总量有限、ID 唯一、时间严格分布；窗口终点进入 `completed`，不回绕 |
| 第三次及后续事件 | 至少跨过第 3、4、5、6 条事件；每条仅应用一次并产生新的候选 ID |
| 滚动规划 | 每次候选硬约束违规为 0；冻结任务的 assignment、资源、路线和四个时间边界不变 |
| 会话兼容 | 旧 2 事件会话不会被新场景误复用；刷新继续找回结构匹配的新会话 |
| 方案内容 | 当前/候选均能读到任务、资源、服务时段、路线、指标和未分配原因 |
| 候选差异 | 页面展示真实计划差异，不以方案 ID 或前端猜测代替 |
| 事件内容 | 页面不依赖初始静态事件元数据也能显示事件类型、航班、事实说明和备注 |
| 自动化 | 前端测试、类型检查、构建及后端全量测试、`compileall`、`pip check`、`git diff --check` 通过 |
| 浏览器 | 真实双服务在桌面和移动端跨越后续事件，无横向溢出、文字重叠或控制台错误 |
