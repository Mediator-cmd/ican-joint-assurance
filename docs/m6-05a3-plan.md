# M6-5A-3 六事件连续空间总验收计划

## 目标

在不新增业务功能或第二状态机的前提下，使用现有六条有限、一次性合成事件完成空间态势最终验收。每一个事件、候选方案、人工决定、资源位置、任务路线和 AI 回答都必须绑定同一个后端 `session_id + revision`，并在断线、重连和服务重启后收敛到 SQLite 权威状态。

> 仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。

## 连续事件矩阵

- 按 08:00、08:04、08:16、08:28、08:40、08:52 的既有事件边界连续运行，不增加第七条事件，不随机生成或循环播放。
- 每次候选等待确认时，空间视图必须完整投影 10 条当前任务路线、5 个资源和 6 个事件；当前事件为 `awaiting_confirmation`，过去事件为 `resolved`，未来事件为 `pending`。
- 候选路线只允许覆盖 `changed_candidate_task_ids`，其数量可以为 0；不得为了视觉效果伪造虚线。10 条当前实线在人工决定前始终保留。
- 交替采用和保留候选。采用后当前方案 ID 必须等于候选 ID；保留后当前方案 ID 不变；两种决定后候选路线均应消失，当前事件转为 `resolved`。
- 每个事件在当前 revision 下执行一次仅规则空间问答，必须引用该事件的 `SPATIAL-FACT-*` 并聚焦当前事件；问答前后运行快照不得发生业务变化。

## 恢复与陈旧态

- 在第三条事件等待确认时重建后端应用与 SQLite repository，候选 ID、revision、仿真时间、事件状态和空间投影必须原样恢复。
- 新 revision 产生后，旧 revision 的空间视图和空间问答请求必须返回 409；浏览器旧回答和 AI 高亮必须清除。
- 浏览器主动中断 SSE 后必须进入两秒 REST 权威快照恢复；解除中断后回到同一会话的实时同步，不允许前端时钟或地图在断线期间自行推进。

## 最终状态与视口

- 第六条事件决定后继续运行至 09:30，状态必须为 `completed`、场景版本 v7、6 个事件全部 resolved、无候选路线。
- 完成后即使外部墙钟继续前进，仿真时间、revision、事件和空间投影不得回绕或生成新事件。
- 在桌面和 390×844 移动视口核对地图、问答、方案和安全声明；文档、地图和回答不得横向溢出，回答自然展开且无内部滚动。
- 浏览器控制台必须为 0 error、0 warning；标准启停脚本必须只操作身份匹配的 8000/4173 服务。

## 禁止事项

- 不新增循环或随机事件、地图专用时钟、前端规划器、随机移动、第二份运行快照或自动候选决定。
- 不接真实机场生产数据、真实坐标、内部机场图、个人信息或外部控制系统。
- AI 不能应用事件、采用/拒绝候选、推进时钟、控制车辆或把旧 revision 的回答作为当前事实。
