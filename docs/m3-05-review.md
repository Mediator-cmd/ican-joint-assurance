# M3-5 审查记录：方案比较、公开审计与兼容演示输出

## 审查范围

- 两套已保存计划的后端指标比较与候选减基线差值。
- 场景审计时间线的公开查询、限额、顺序和脱敏边界。
- `/api/v1/demo` 对现有 `DemoPayload` 和安全声明的兼容性。
- FIFO → 事件 → CP-SAT → 比较 → 审计的完整 HTTP 闭环。

## 新增接口

| 方法与路径 | 作用 | 关键边界 |
| --- | --- | --- |
| `POST /api/v1/scenarios/{scenario_id}/comparisons` | 比较两套已保存计划 | 允许跨版本，不允许跨场景或同一计划自比 |
| `GET /api/v1/scenarios/{scenario_id}/audit-records` | 查询最近的场景审计记录 | `limit` 为 1-100，返回结果保持正序 |
| `GET /api/v1/demo` | 提供网站兼容演示数据 | 复用确定性导出器，不在路由复制调度公式 |

## 比较契约与结论规则

比较响应包含基线/候选计划 ID、场景版本、算法、已安排/未安排任务、任务完成率、紧急任务保障率、平均/最长等待、综合资源利用率、违规数及所有候选减基线差值。

结论采用固定优先级：先比较硬约束违规数，再比较紧急任务保障率和整体任务完成率，最后比较平均及最长等待。资源利用率作为负载信息展示，不被简单解释为越高越好。结论和建议均由结构化规则生成，并始终要求人工复核。

演示闭环中，候选方案较基线多安排 1 项任务，任务完成率提高 20 个百分点，紧急任务保障率提高 50 个百分点；代价是平均等待增加 6.35 分钟、最长等待增加 20 分钟，违规数差值为 0。因此响应明确建议优先复核候选方案，同时提示核对等待和资源负载。

## 一致性与安全审查

1. 比较前确认两套计划都存在且属于路径指定场景；缺失计划沿用 `plan_not_found`，跨场景返回安全业务错误。
2. 计划可以来自同一场景的不同版本；比较不要求或修改 `expected_version`。
3. 比较只在仓储锁内追加一条 `comparison_created` 审计，不改变场景版本、历史快照或计划内容。
4. 审计记录继续使用防御性深拷贝；公开字段不包含本地路径、原始请求、异常文本或个人信息。
5. `/demo` 直接调用 `demo_export.py`，不在 API 路由或前端复制事件应用、FIFO、CP-SAT 和指标计算。
6. 安全声明精确保持为：`仅供教学仿真与辅助决策使用，不构成真实机场运行、放行、登机、改签或车辆控制指令。`
